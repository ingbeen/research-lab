## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

2026-09-29 `docs/DEFERRED_FINDINGS.md` 를 처리 순서대로 조사했다(항목마다 지금 코드에서 재현 → 표 → 사용자 선택). 사용자가 추천안을 채택했고, 이 계획서는 그중 「고친다」 일곱 항목을 맡는다. 재현은 세션 스크래치의 스크립트로 했고 저장소 파일은 건드리지 않았다.

| 미룬 지적 | 재현 | 실제 산출물에서 | 무게 |
| --- | --- | --- | --- |
| 정성 표현 게이트 큰 정수 오버플로 | `candidates: [10**400, 5]` 에서 `OverflowError`. `json.loads` 가 401자리 정수를 그대로 넘긴다 | 수집 산출물 14개 · 축 26개 · 후보값 83개 중 0건 | 무거움(죽는다) |
| 목록 모양 어림 근거 | 목록 · 사전 근거가 둘 다 「어림 근거: 적지 않았습니다」 | 가동일 필드가 든 탐색 산출물 자체가 0건(기준 도입 뒤 돈 회차 0회) | 가벼움 |

| 원장 머리말 `- [-]` 뜻 | 머리말 · `Status.REJECTED` 주석이 「잴 수 없다고 판정한 것」 | **1건** — 실제 원장의 관리종목 해제 후보(사람이 가동일로 기각) | 그 외 |

**같은 모양을 더 찾았다** — 「사유의 값 자리를 한 글자 조각으로 단언」하는 모양이 게이트 쪽 `test_reason_carries_the_estimates_and_the_threshold` 에도 있고(「4」 · 「48」), `test_missing_basis_is_said_out_loud` 는 「근거」를 단언하는데 이 글자는 사유의 고정 문구 「어림 근거:」에 **늘** 들어 있어 근거가 빠졌다는 사실을 못 가른다. 둘 다 이 계획서가 함께 고친다.

**목표 1 의 수정 방향은 항목 본문의 제안과 다르다.** 항목은 가동일 게이트처럼 `OverflowError` 를 잡아 「못 읽음」으로 두자고 했지만, 두 게이트에서 「못 읽음」의 결과가 반대다 — 가동일 게이트는 판정 못 함 → **통과**(안전)이고, 정성 표현 게이트는 숫자 후보가 모자람 → **영구 기각**이다. 그대로 옮기면 지금의 「예외 → 재시도(다시 물으면 대개 다른 답)」가 「첫 답에서 영구 기각」으로 바뀐다. 대신 `float()` 변환을 **뺀다**. 파이썬은 값이 같은 정수와 실수의 해시를 같게 두므로 집합이 이미 둘을 하나로 센다. [실측 2026-09-29] `{5, 5.0}` → 1개 · `{0, -0.0}` → 1개 · `{10**400, 5}` → 2개 · JSON 의 `[NaN, NaN]` → 1개(같은 객체) — 지금 판정되던 모든 입력의 결과가 같고, 큰 정수만 예외 대신 숫자 후보로 세인다.

### 되돌리기 어려운 결과에 물리는 판정 — 실제 산출물에 돌린 결과

목표 1 은 수집 기각(영구)에 물린 판정을 바꾼다. 바뀌는 입력은 「실수 범위를 넘는 정수 후보값」 하나이고, 실제 수집 산출물 14개의 후보값 83개 중 0건이다. **Phase 1 Validation 에서 실제 산출물 14개 전부에 변경 전후 판정을 돌려 결과가 같음을 확인한다.** 나머지 목표는 판정 결과를 바꾸지 않는다(사유 글자 · 로그 문구 · 문서 · 테스트).
