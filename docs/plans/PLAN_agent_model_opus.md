- 사용자가 **Opus 5.5 · xhigh** 로 돌리기를 원한다

### 고치는 방식과 탈락안

- **`invoke.build_command` 에 두 플래그를 상수로 넣는다.** 호출하는 곳이 `scripts/run_cycle.py` 한 곳이고 모든 단계가 이 함수를 지나므로, 단계가 늘어도 빠지지 않는다. 호출 계층은 「어느 단계가 자기를 쓰는지 몰라야 한다」는 계약과도 맞다 — 단계마다 다른 모델을 줄 이유가 지금 없다
- **모델은 별칭(`opus`)이 아니라 전체 ID(`claude-opus-5-5`)로 적는다.** 별칭은 다음 Opus 가 나오는 날 가리키는 대상이 바뀐다 — 이번 작업이 막으려는 「조용히 바뀐다」가 그대로 남는다
- **effort 는 반드시 명시한다.** Opus 5.5 는 안 주면 `medium` 이다
- **Dockerfile 의 설치를 `@anthropic-ai/claude-code@2.1.280` 로 고정한다.** 모델이 2.1.280 이상을 요구하고, 고정이 없으면 빌드할 때마다 응답 모양 등 CLI 동작이 에러 없이 바뀔 수 있다. 대가는 새 모델을 쓰려면 버전을 손으로 올려야 한다는 것 — 그 사실을 Dockerfile 주석에 적는다

| 탈락안 | 왜 버리나 |
| --- | --- |
| 저장소 `.claude/settings.json` 에 `model` · `effortLevel` | 컨테이너 회차뿐 아니라 **사용자가 이 저장소에서 여는 대화 세션의 모델까지 바뀐다** |
| 실행 인자(`--model` · `--effort`)로 받아 예약 정의에 박는다 | `usage.py` 가 밝힌 이 저장소의 관용 — 「예약 실행의 작업 정의에 값이 하나 더 박히면 기본값을 고치는 날 예약 회차의 동작이 조용히 달라진다」 |
| 환경변수로 넘긴다 (실행 스크립트) | 값이 코드 밖 두 곳(실행 스크립트 · 러너의 환경 허용 목록)에 흩어지고, 인자 계약 테스트로 고정할 수 없다 |
| CLI 버전을 고정하지 않고 최신으로 다시 빌드 | 사용자 결정으로 탈락 — 위 「조용히 바뀐다」 |
