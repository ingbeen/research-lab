### 고치는 방식

- **`build_command` 가 프롬프트를 받지 않는다.** 인자 목록에 프롬프트 자리가 **구조적으로** 없어진다 — 「인자에 싣지 않는다」를 주석이 아니라 시그니처로 지킨다
- **`invoke` 가 `subprocess.run(..., input=prompt)` 로 넘긴다.** 모든 단계가 이 함수 하나를 지나므로 판정뿐 아니라 **산출물이 커지는 어느 단계**에서도 같은 일이 안 생긴다(전역 규칙 「증상이 아니라 근원을 고친다」)
- **인코딩을 `encoding="utf-8"` 로 명시한다.** 인자는 파일시스템 인코딩(UTF-8)으로 바이트가 됐지만 표준 입력은 **로캘 인코딩**을 따른다. 컨테이너는 UTF-8 이라 지금은 같지만(실측: `locale.getpreferredencoding` → `UTF-8`), 호스트에서 직접 돌리면 셸 로캘을 따른다. 전송 경로를 바꾸면서 새로 생기는 의존이라 이번 범위에 넣는다. 응답(stdout · stderr) 디코딩도 같은 인자로 UTF-8 이 된다 — CLI 는 UTF-8 JSON 을 낸다
- 인자에 남는 가장 큰 값은 `--json-schema` 문자열로 **750B**(기제) · 560B(측정 설계) · 352B(판정)라 상한과 거리가 멀다

#### [실측 2026-09-26] CLI 가 인자 없이 표준 입력만으로 프롬프트를 받는가

공식 문서(`code.claude.com/docs/en/headless`)는 「`-p` 모드는 표준 입력을 읽는다 · 파이프 입력 상한 10MB · 넘으면 명확한 오류와 0 이 아닌 종료 코드」까지만 말하고, **위치 인자 없이 표준 입력만 줄 때**는 명시하지 않는다. 그래서 이미지 안 CLI(`2.1.280`)로 쟀다. 러너가 쓸 경로와 같게 파이썬 `subprocess.run(..., input=...)` 로 불렀고, 플래그는 `build_command` 와 같은 조합(`--output-format json` · `--session-id` · `--permission-mode bypassPermissions` · `--max-budget-usd` · `--tools` · `--json-schema`)에 **모델만 Haiku 4.5** 로 바꿨다(전달 방식과 무관한 비용 절감)

**세션 로그로 교차 확인했다.** 두 회 모두 모델이 받은 첫 사용자 메시지가 **표준 입력 글 그대로**다 — 감싸는 문구가 없고, 바이트 수가 보낸 것과 **정확히 같다**(175,695 · 145,796). 그래서 1회도 끝의 표식까지 닿았고 거절은 내용(「위 글은 무시하라」는 주입 모양) 때문이었다. 운용 회차(인자로 넘긴 프롬프트)의 첫 메시지도 **같은 모양**(문자열 그대로)이라, 표준 입력으로 바꿔도 단계 지시문이 「파이프로 들어온 자료」처럼 격이 낮아지지 않는다.

## 7) 리스크(Risks)

- **CLI 가 표준 입력과 위치 인자를 함께 받으면 합친다** — 문서의 `cat 파일 | claude -p "지시"` 예시가 그 모양이다. 위치 인자를 **아예 두지 않는** 것으로 피하고, 인자 목록에 프롬프트가 없다는 테스트로 고정한다
- **파이프 입력 상한 10MB** — 판정 프롬프트(136,063B)의 약 70배라 멀다. 넘으면 CLI 가 명확한 오류와 0 이 아닌 종료 코드를 낸다고 문서가 말하므로 원문이 실패 줄에 남는다(「그 외」로 재시도). 설계서 §11.16 「못 덮는 곳」에 적는다
- **표준 입력 전달을 잰 것은 Haiku 한 모델이다** — 전달은 CLI 가 모델을 부르기 «전»의 일이라 모델과 무관하다. Opus 로의 첫 확인은 후속의 이어받기 회차가 된다
- **가짜 실행 파일 테스트가 플랫폼을 탄다** — 첫 줄(shebang)에 `sys.executable` 절대경로를 쓰고 실행 권한을 준다. 리눅스 · mac 모두 표준 동작이다. `PATH` 를 그 폴더 하나로 좁혀도 절대경로라 인터프리터를 찾는다
- **응답 디코딩이 로캘에서 UTF-8 로 바뀐다** — CLI 는 UTF-8 JSON 을 내고 컨테이너 로캘도 UTF-8 이라 운용 경로의 동작은 같다
- **표준 입력을 물려받던 동작이 사라진다** — 지금은 러너의 표준 입력을 CLI 가 물려받는다(컨테이너에서는 입력이 붙지 않은 상태, 호스트에서는 터미널). 파이프로 바뀌면 쓰고 닫으므로 CLI 가 무언가를 기다리며 멈출 여지가 오히려 줄어든다
- **CLI 가 입력을 다 읽기 전에 끝나면 쓰기가 `BrokenPipeError` 가 된다**(인증 거부처럼 시작하자마자 끝나는 경우) — 파이썬 `communicate()` 가 그 예외를 **삼키도록 돼 있다**(표준 라이브러리 `subprocess.py` 의 「communicate() must ignore BrokenPipeError」). 그래서 새 예외 경로가 생기지 않고, 판정은 지금처럼 종료 코드와 stdout 으로 한다
