## 3) 배경/맥락(Context)

### 현재 문제점 / 동기

- 모델을 Opus 5.5 · xhigh 로 고정한 뒤(직전 커밋) **보정값 1,900,000 은 Sonnet 5 로 잰 값**으로 남아 있다. 회차 로그의 한도 비율이 실제보다 1.5 ~ 1.8배 크게 찍힌다
- 단계 상한 $4 는 Sonnet 실측 최대의 약 1.6배로 정한 값이다. Opus 에서 최대가 $3.0299 로 올라 여유가 1.3배로 줄었다
- 운용 문서 §5.2 와 설계서 §11.9 는 「CLI 에 사용량 명령이 없다」 · 「관찰자 몫은 0 이 안 된다」고 적고 있다. 오늘 둘 다 사실이 아님을 확인했다

#### 실측 (2026-09-23) — 두 회차 모두 Opus 5.5 · xhigh · `--budget-usd 8` · 1장 · 수집부터 판정까지 7단계

| | 1차 | 2차 |
| --- | --- | --- |
| 시작 → 종료 | 10:21:05 → 11:01:46 | 17:06:08 → 17:54:59 |
| 5시간 창 (호스트 `claude -p "/usage"`) | 72% (10:20:40) → 94% (10:59, 사용자 화면 캡처) = **22%p** | 13% (17:04:02) → 40% (17:54:59) = **27%p** |

- 두 역산이 **약 4% 안에서** 맞는다 → `2,900,000`
- **`/usage` 는 모델을 부르지 않는다** — `claude -p "/usage" --output-format json` 이 `total_cost_usd: 0` · `num_turns: 0` · `duration_api_ms: 0` · `modelUsage: {}`
- **회차 토큰(장기 토큰)으로 컨테이너에서 부르면 사용률이 안 나온다** — 그 세션의 비용 요약(`Total cost: $0.0000` …)만 나온다. 사용률은 호스트 로그인으로만 보인다
- 전 → 회차 → 후 를 **백그라운드 스크립트 하나**로 묶어, 재는 쪽 세션의 요청이 구간 안에 들어가지 않았다(관찰자 몫 ≈ 0)

### 고치는 방식

- `usage.CALIBRATION` 값과 날짜를 바꾸고, 그 위 주석의 「어떻게 쟀나 · 오차 방향」을 새 측정에 맞게 다시 쓴다. 🔴 **「이 값은 창의 하한 → 비율이 크게 나온다(안전한 방향)」는 보증은 더 이상 서지 않는다** — 관찰자 몫이 없어졌고 남은 오차(정수 %)는 양쪽으로 난다. 사실대로 적는다
- `LimitCalibration` 문서 주석의 「CLI 에 사용량 명령이 없다」를 「사용률은 사람의 로그인으로만 보이고 회차 토큰으로는 안 보인다 — 그래서 러너가 못 읽는다」로 고친다
- `DEFAULT_BUDGET_USD = 5.0` — 주석에 Opus 실측 최대와 1.6배 규칙을 적는다. Sonnet 시절 $2 → $4 의 사고 기록은 남긴다
- `DEFAULT_CYCLE_DOSSIERS` 주석의 「한 장이 약 23%」에 Opus 실측(22 ~ 27%)을 더한다 — 값은 그대로
- 테스트 `test_the_step_guard_clears_the_most_expensive_step_ever_measured` 의 실측 최대를 $3.0299 로 바꾸고, **「약 1.6배 위」를 단언**한다. 지금 테스트는 `>` 만 봐서 $4(1.3배)도 통과시켰다 — 주석이 말하는 여유를 테스트가 지키지 못하고 있었다
