### 고치는 방식과 탈락안

- **실패 예외가 «그 호출이 쓴 것»을 함께 나른다.** `steps.StepFailed(raw, *, spent=None)` — `spent` 는 그 호출의 `AgentResult`(비용 · 토큰 · 성분 · `session_id`). 분류는 여전히 원문으로 하므로 `failures` 는 안 바뀐다
- **`invoke.py` 가 응답 JSON 에서 `AgentResult` 를 만드는 부분을 한 곳으로 모은다.** 성공 경로(`_parse`)와 실패 경로(종료 코드 ≠ 0 · `is_error`)가 같은 helper 를 쓴다. stdout 이 JSON 객체가 아니면 `None`. `parse_json_answer` 실패는 받은 `result` 를 그대로 싣는다. 시간 초과는 `None`
- **러너(`cycle._execute_with_retries`)가 적는다.** `StepFailed` 계열을 잡는 두 갈래에서 `spent` 가 있으면 **실패 줄 «앞»**에 `decision_log.record_cost` 로 비용 줄을 남긴다
- **같은 `session_id` 의 비용 줄이 이미 있으면 적지 않는다 — 그 검사는 `record_cost` 안에 둔다.** 지금은 8개 단계가 모두 파싱 «뒤»에 `record_cost` 를 불러 겹칠 일이 없다. 그러나 그 순서는 **8개 모듈에 흩어진 관용**이라, 한 단계가 `record_cost` 를 파싱 앞으로 옮기는 순간 **같은 호출이 두 번 세이고 에러가 안 난다.** `session_id` 는 호출마다 미리 정한 UUID 라(`invoke.new_session_id`) 겹침을 기계로 가를 수 있다. 검사를 러너가 아니라 **비용 줄을 쓰는 함수 하나**에 두는 것은 패키지 계약 §12 「같은 가드를 두 곳에 두지 않는다」와 결정 로그가 그 열쇠의 주인이라는 관용을 따른 것이다 — 러너에 두면 단계 쪽 호출은 여전히 겹칠 수 있다
- **`session_id` 가 비면 미리 정한 값을 쓴다.** 지금 `_parse` 는 `str(payload.get("session_id", session_id))` 라, 응답에 열쇠가 «있고» 값이 `null` 이면 **문자열 `"None"`** 이 된다(패키지 계약 §12 의 그 함정). 그러면 서로 다른 호출이 같은 열쇠를 가져 **중복 검사가 멀쩡한 비용 줄을 버린다.** helper 로 옮기면서 「비었거나 문자열이 아니면 미리 정한 값」으로 좁힌다
- **비용 0 인 줄도 적는다.** 호출 시작에서 거부된 한도(09-19 ~ 09-21 모양)는 비용 0 · 토큰 0 줄이 생긴다. 「재서 0 이었다」를 「잴 수 없었다」와 가르는 것이 이 로그의 관용이다(`record_cost` 의 주석). 합계는 안 바뀌고, 토큰이 0 이면 한도 비율은 지금처럼 「잴 수 없음」이다

| 탈락안 | 왜 버리나 |
| --- | --- |
| 8개 단계 모듈에서 `record_cost` 를 파싱 «앞»으로 옮기고, 호출 실패만 러너가 적는다 | 8곳 편집. **새 단계가 순서를 어기면 다시 조용히 샌다** — 순서 의존이 그대로 남는다 |
| 진입점의 호출자(`ask`) 한 곳에서 모든 비용을 적는다 | 순서 의존은 없지만 8개 단계의 `record_cost` 를 걷고 그것을 고정한 단계 테스트를 고쳐야 한다. **비용 기록이 러너 밖(`scripts/`)으로 나간다** |
| 실패 원문(`raw`)을 러너가 정규식으로 읽는다 | `invoke` 가 만드는 메시지 모양(`--- stdout ---`)에 러너가 묶인다. **응답 모양을 아는 쪽은 `invoke` 하나여야 한다** |

**계층 방향** — `agent` 는 이미 `runner.steps.StepFailed` 를 import 한다(기존). `steps.py` 가 `AgentResult` 타입을 가리킬 때는 `TYPE_CHECKING` 으로만 가져와 **런타임 순환 import 를 만들지 않는다.**

## 7) 리스크(Risks)

- **같은 호출을 두 번 센다** — 단계가 이미 적은 호출을 러너가 또 적는 경우. `session_id` 중복 검사와 그 테스트로 막는다
- **`session_id` 가 비어 중복 검사가 멀쩡한 줄을 버린다** — 응답에 열쇠가 없으면 미리 정한 값을 쓰는 기존 관용에 더해, 값이 `null` 이어도 미리 정한 값을 쓰게 좁힌다. 테스트로 고정한다
- **`record_cost` 가 부를 때마다 로그를 읽는다** — 한 폴더의 로그는 수십 줄이고 호출은 단계당 한 번이라 비용이 무시할 만하다
- **기존 테스트의 가짜 응답이 `session_id="세션"` 을 고정으로 쓴다**(8개 파일) — 한 폴더에서 여러 번 부르는 테스트는 중복 검사로 비용 줄이 하나만 남는다. 비용 줄 «수»를 세는 기존 테스트는 없어 깨지지 않음을 확인했다(`grep` 2026-09-23). 새 테스트는 호출마다 다른 `session_id` 를 쓴다. 운용 경로는 호출마다 새 UUID 라 해당 없다
- **순환 import** — `steps.py` 가 `AgentResult` 를 런타임에 import 하면 `invoke` ↔ `steps` 가 돈다. `TYPE_CHECKING` 으로만 가져온다
- **비용 0 인 줄이 늘어난다** — 시작 시점에 거부된 한도마다 한 줄. 합계와 비율은 안 바뀌고, 「재서 0」이라는 정보가 남는다
- **실패 응답의 `usage` 모양이 성공과 다르다** — helper 가 아는 열쇠만 꺼내고 없으면 `None` 으로 두는 기존 관용을 따른다. 판정을 못 해도 회차를 멈추지 않는다
- **회차 로그 값이 전후로 불연속** — 2026-09-23 이전 줄에는 실패 비용이 없다. 설계서 §11.14 에 그 경계를 적는다
