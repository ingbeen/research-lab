# 운용 — 트리거를 붙이고, 기계를 옮긴다

> 이 문서는 **그 기계의 OS 설정**을 다룹니다. 저장소의 실행 명령어와 그 옵션의 뜻은
> [COMMANDS.md](COMMANDS.md) 가 단일 SoT 이며 여기에 복제하지 않습니다.
>
> **등록은 제가 합니다. 사용자 손에 남는 것은 둘입니다** (2026-09-15 결정) —
> **`sudo` 가 필요한 절전 해제 예약**과 **패키지·런타임 설치**(엔진 · Python · Poetry).
> 등록은 아무것도 «설치»하지 않고 아래 절차를 적용할 뿐이라, 무엇이 이 기계에 설치되는지를
> 쓰는 사람이 통제한다는 원칙이 그대로 지켜집니다.
>
> **그래도 절차를 문서로 남깁니다** — 기계를 옮기는 날 필요한 것은 「누가 눌렀나」가 아니라
> **무엇을 왜 그렇게 등록하나**입니다.

## 1. 운용기는 mac 입니다 (2026-09-14 결정)

| 후보 | 붙이는 것 |
| --- | --- |
| **mac (채택)** | `launchd` + `pmset` 절전 해제 + `caffeinate` + **엔진 자동 시작** |
| WSL | Windows 작업 스케줄러의 「절전 모드 해제」 옵션 + `wsl.exe -- docker run …` |

**근거**: 파이프라인을 지은 뒤 세 단계가 전부 mac 에서 돌았고, 원래 설계도 「최종 운용은
mac 한 대」였습니다. 컨테이너로 싸 둔 덕에 **옮길 때 바뀌는 것이 트리거뿐**이라는 전제는
그대로이며, 그 전제를 실제로 쓰는 자리가 아래 7절입니다.

> **[결정 2026-09-26] WSL 에는 당분간 예약을 걸지 않고, 사람이 직접 돌립니다.**
> 확인해 보니 WSL 은 예약으로 돈 적이 한 번도 없습니다 — cron · systemd 타이머 ·
> Windows 작업 스케줄러 어디에도 등록이 없고, 예약 시각에 시작한 회차 기록은 전부 mac 에서
> 들어왔습니다. 회차가 도는 데 필요한 것(2절의 확인 항목과 컨테이너 이미지)은 갖춰져 있어
> **빠진 것은 트리거뿐**입니다.
>
> 나중에 WSL 에 예약을 붙이려면 **절차부터 새로 씁니다** — 위 표의 한 줄이 전부이고
> `scripts/trigger.sh` 는 mac 전용입니다. 「작업 스케줄러가 잠든 PC 를 깨워 WSL 과 엔진을
> 띄우고 회차까지 이어지는가」는 **[미검증]** 이며, 4.1 의 찔러보기를 WSL 방식으로 옮겨
> 재는 것이 첫 자리입니다.
>
> 🔴 **mac 예약을 다시 켤 때는 WSL 에서 손으로 돌리는 회차와 겹치지 않게 합니다.**
> 잠금은 기계를 넘지 못해서, 두 기계가 같은 원장과 `runs/` 를 각자 고치면 git 으로
> 합칠 때 충돌합니다.

## 2. 착수 전 확인 — 읽기 전용

셋 다 **없으면 회차가 시작 자체를 거부**하거나 조용히 안 돕니다.

```bash
# ① 무인 실행용 장기 토큰이 있는가.
#    [주의] 환경변수로 «재지 않습니다» — 토큰은 파일에 있고 셸에 export 돼 있지 않습니다.
#    자리는 루트 CLAUDE.md 가 정한 저장소 밖 키 폴더이며, 없으면 'claude setup-token' 으로 한 번만 발급합니다
[ -s ~/.claude/keys/research-lab-oauth-token ] && echo "토큰 파일 있음" || echo "토큰 파일 없음"

# ② API 키가 «없어야» 한다. 있으면 구독 대신 API 로 과금된다
[ -n "${ANTHROPIC_API_KEY+x}" ] && echo "[위험] API 키가 설정돼 있다" || echo "API 키 없음 (정상)"

# ③ 컨테이너 런타임이 떠 있는가
docker info >/dev/null 2>&1 && echo "도커 정상" || echo "도커가 안 떠 있다"
```

🔴 **① 을 환경변수로 재면 「없음」이 나오는데 그것이 「발급 안 됨」이 아닙니다.** 토큰은
파일로만 두고 예약 작업이 실행 시점에 읽어 갑니다(3.1절) — 그래야 **사본이 한 벌**이고
토큰을 새로 발급할 때 작업 정의 파일을 고칠 일이 없습니다.

🔴 **③ 이 이 기계의 약한 고리입니다.** 도커 엔진이 VM 위에 있어서 **재부팅하면 엔진이
내려가고, 다시 띄우기 전까지 예약 회차가 매번 실패합니다.** 종료 코드로는 그냥 실패로
보일 뿐 「도커가 안 떠 있다」로는 안 보입니다.

> **[실측 2026-09-14] 이 기계의 엔진은 로그인 시 «자동으로 뜨지 않았습니다».**
> 서비스로 등록돼 있지 않고, 사용자·시스템 영역의 자동 실행 목록 어디에도 항목이 없었으며,
> **엔진 프로세스의 시작 시각이 부팅 시각보다 열나흘 늦었습니다**(사람이 손으로 띄운 것).
> 그때까지 돌던 이유는 **재부팅이 없었기 때문**입니다 — 무인 운용의 전제로 삼을 수 없어
> 아래 3.0 절에서 자동 시작을 등록합니다.

## 3. 트리거 등록 — `sudo` 한 줄만 사용자입니다

예약 시각은 **매일 01:00 (KST)** 입니다. 근거는 사용 한도가 「첫 프롬프트부터」 5시간
창으로 돌기 때문이고, 낮에 직접 쓰는 시간대와 겹치지 않는 쪽이 유리합니다.

### 3.0 컨테이너 엔진을 «로그인과 같이» 띄운다 (2026-09-14 결정)

2절 ③ 의 실측대로 엔진은 스스로 뜨지 않으므로 **서비스로 등록**합니다.
homebrew 로 깐 엔진이면 한 줄입니다.

```bash
brew services start colima
brew services list          # 등록 확인 — 상태가 'started' 여야 한다
```

**예약 작업과 «같은 수명»을 갖는 것이 이 선택의 이유입니다.** 아래에서 만드는 작업도
사용자 로그인 세션에 등록되므로, 엔진을 같은 자리에 두면 **둘이 함께 뜨고 함께 내려갑니다** —
「작업은 떴는데 엔진이 없어 매일 실패하는」 어긋남이 구조적으로 안 생깁니다.

| 탈락안 | 왜 버리나 |
| --- | --- |
| **회차를 띄울 때 함께 엔진을 시작한다** | 01:00 에 **VM 부팅이 실패하는 모드가 하나 늘고**, 그 코드가 실행 스크립트에 들어가면 이 기계·이 엔진 전용이 되어 **7절이 약속한 「옮길 때 바뀌는 것은 트리거뿐」이 깨집니다** |
| 그대로 두고 재부팅한 날 손으로 띄운다 | 무인 운용에는 그것을 기억할 사람이 없습니다. **실패가 「엔진이 없다」로 안 보이는 것**이 2절 ③ 의 내용입니다 |

🔴 **등록 직후의 「stopped」를 고장으로 읽지 마세요 — 그리고 「등록됐다」로도 읽지 마세요.**
이미 손으로 띄운 엔진이 돌고 있으면 서비스는 뜰 때마다 **「이미 돌고 있음」으로 즉시 끝나고
10초마다 다시 뜨는 공회전**이 됩니다. 목록에는 `stopped` 으로 보이고 엔진은 정상이라,
**둘 중 무엇이 VM 을 쥐고 있는지가 목록에 안 나옵니다.**

**갈라 보는 법은 하나입니다 — 손으로 띄운 것을 내리고 서비스가 스스로 올리는지 봅니다.**
그 조합이 **깨끗한 부팅과 같은 조건**입니다.

```bash
colima stop                 # 손으로 띄운 것을 내린다
brew services list          # 상태가 started 로 바뀌어야 한다
docker info                 # 조금 기다린 뒤 정상이어야 한다
```

> **[실측 2026-09-15] 이 기계에서는 24초에 복귀했습니다** — 사람 손 0.
> 그 전까지는 위 공회전 상태였고, **목록만 보고 넘겼다면 그대로 굳었을 것입니다.**

### 3.1 작업 정의 파일을 만든다

`~/Library/LaunchAgents/local.research-lab.cycle.plist` 로 저장합니다.
**저장소 «밖»입니다** — 이 저장소는 PUBLIC 입니다.

🔴 **토큰을 이 파일에 «적지 않습니다».** 실행 시점에 키 파일에서 읽어 넘깁니다.
적으면 자격증명 사본이 두 벌이 되어 **토큰을 새로 발급할 때마다 두 곳을 고쳐야 하고,
한 곳을 잊으면 예약 회차가 만료된 토큰으로 조용히 실패합니다.**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>local.research-lab.cycle</string>

  <key>ProgramArguments</key>
  <array>
    <!-- 토큰은 키 파일에서 실행 시점에 읽는다. 이 파일에는 자격증명이 들어가지 않는다.
         로그인 셸로 열지 않는다('-lc' 금지) — 프로필이 ANTHROPIC_API_KEY 를 들여올 수 있다.
         caffeinate 로 감싼다. 회차가 길어질 수 있어 도는 중에 다시 잠들면 안 된다 -->
    <string>/bin/sh</string>
    <string>-c</string>
    <string>export CLAUDE_CODE_OAUTH_TOKEN="$(cat /Users/사용자이름/.claude/keys/research-lab-oauth-token)"; exec /usr/bin/caffeinate -i /Users/사용자이름/Workspace/research-lab/docker/run.sh --cycle-dossiers 4</string>
  </array>

  <key>StartCalendarInterval</key>
  <dict>
    <key>Hour</key><integer>1</integer>
    <key>Minute</key><integer>0</integer>
  </dict>

  <key>EnvironmentVariables</key>
  <dict>
    <!-- launchd 는 로그인 셸의 환경을 «물려받지 않는다». 넘길 것을 여기 적어야 한다 -->
    <key>PATH</key>
    <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
  </dict>

  <key>StandardOutPath</key>
  <string>/Users/사용자이름/Library/Logs/research-lab/cycle.out.log</string>
  <key>StandardErrorPath</key>
  <string>/Users/사용자이름/Library/Logs/research-lab/cycle.err.log</string>
</dict>
</plist>
```

🔴 **여기서 조용히 틀어지는 자리가 셋입니다.**

| 자리 | 안 하면 |
| --- | --- |
| **`PATH` 를 적는다** | launchd 의 기본 경로에는 `docker` 가 없습니다. 회차가 「명령을 못 찾음」으로 끝나는데, **로그를 안 보면 그냥 안 돈 것처럼 보입니다** |
| **`--cycle-dossiers` 를 «명시»한다** | 기본값에 기대면 나중에 그 기본값을 고치는 날 **예약 회차의 동작이 조용히 달라집니다.** 그리고 플래그 «이름»이 바뀌면 예약이 **인자 오류로 죽습니다** — 그때는 `runs/cycles.jsonl` 에 줄이 아예 안 남고 `cycle.err.log` 에만 사유가 남으므로, 아래 「12시 이후 줄이 아예 없다」와 같은 갈래로 읽고 **트리거 쪽**을 봅니다 |
| **`ANTHROPIC_API_KEY` 를 «안» 적는다** | 적으면 그 순간 구독 대신 API 로 과금됩니다. launchd 가 환경을 안 물려받는 것이 여기서는 **안전판**이니 그대로 둡니다 |

**로그 폴더를 미리 만들고, 좁혀야 할 권한은 «키 파일» 쪽인지 확인합니다.**
작업 정의 파일에는 자격증명이 없습니다.

```bash
mkdir -p ~/Library/Logs/research-lab
ls -l ~/.claude/keys/research-lab-oauth-token   # 권한이 600 이어야 한다
```

### 3.2 등록한다

```bash
./scripts/trigger.sh on
```

**예전에 껐던 기계라면 이 쪽을 씁니다.** `disable` 기록이 남아 있으면 `bootstrap` 만으로는
`Bootstrap failed: 5: Input/output error` 로 거부되는데, 스크립트가 `enable` 을 먼저
걸어 그 자리를 덮습니다(8.1절). 처음 등록하는 기계에서는 아래와 같습니다.

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.research-lab.cycle.plist
```

### 3.3 잠든 기계를 깨운다

**예약 장치는 기계를 깨우지 않습니다** — 그래서 예약 시각보다 조금 앞서 따로 깨웁니다.
**이 한 줄만 `sudo` 가 필요합니다.**

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 00:55:00
```

🔴 **「그 시각에 못 돈다」와 「아예 안 돈다」를 헷갈리지 마세요.** 잠든 동안 시각이 지나가면
회차는 **그 시각에** 못 돌고, **깨어난 뒤에 늦게** 도는 것으로 알려져 있습니다.
**[확인됨 2026-09-16]** 사용자가 이틀에 걸쳐 실측으로 확인했습니다 — 이 항목은 닫혔습니다.

**이 구별이 내일 결과를 읽는 방식을 바꿉니다.**

| 회차가 돈 시각 | 읽는 법 |
| --- | --- |
| 예약 시각 그대로 | **기계가 그 시각에 깨어 있었다** — 잠들어 있었다면 깨우는 쪽이 동작한 것이다 |
| 사람이 기계를 쓰기 시작한 시각 | **깨우지 못했고, 예약 장치가 늦게 따라잡았다** — 무인 운용이 아니라 「사람을 기다린 운용」이다 |
| 안 돌았다 | 둘 다 아니다. 로그와 종료 코드부터 본다 |

> 🔴 **그 판정에서 조회 둘을 「답」으로 읽지 마세요.** `pmset -g sched` 가 **빈 출력**이었고
> `pmset -g log` 에도 01:00 전후 wake 가 없었지만, 그 둘은 **「지금 반복 예약이 걸려 있나」**를
> 말할 뿐 **「잠든 기계가 그 시각에 깨어나나」**의 답이 아닙니다 — 깨우는 수단은 반복 예약
> 말고도 있습니다(전원 연결 시 잠들지 않게 두는 설정 등).
>
> 그 구분을 놓치고 「등록이 없으니 안 돈다」고 적었다가 사용자의 실측으로 거뒀습니다.
> **이 저장소가 권한 비트를 추론했다 틀린 것과 같은 갈래**이고, 아래 3.3 은 반복 예약을
> 쓰는 경우의 절차로 남깁니다.

## 4. 등록 뒤 확인 — 읽기 전용

```bash
# 등록됐나 — 「지금」과 「재부팅 후」를 갈라 봅니다 (8.1절)
./scripts/trigger.sh status

# 원시 출력으로 교차 확인
launchctl print gui/$(id -u)/local.research-lab.cycle | head -20

# 엔진도 함께 뜨게 돼 있나 (3.0절)
brew services list

# 다음 절전 해제 예약
pmset -g sched

# 지난 회차가 어떻게 끝났나
tail -40 ~/Library/Logs/research-lab/cycle.err.log
```

🔴 **위 명령이 찍는 환경 목록을 «실행 환경»으로 읽지 마세요.** `HOME` 처럼 실행 시점에야
들어오는 값이 목록에 없습니다. **[실측 2026-09-15]** 목록에 없어서 「HOME 이 없다」고
판정했는데 실제로는 들어왔습니다 — 나열된 것으로 판정하면 틀립니다. 재는 법이 아래에 있습니다.

### 4.1 예약 실행 경로를 «$0 로» 찔러 본다

**회차 하나는 $2~5 인데 이 확인은 0 입니다.** 진입점의 도움말만 출력하게 하면
에이전트를 한 번도 부르지 않으면서 **토큰 파일 읽기 · `PATH` · 엔진 소켓 · 컨테이너
진입점**이 한 줄로 이어지는지 드러납니다. **새 기계로 옮길 때마다 값이 있습니다** —
배선이 깨졌다면 돈을 쓰기 «전»에 나옵니다.

3.1 절의 작업 정의를 복사해 **네 곳만** 바꿉니다.

| 바꿀 것 | 무엇으로 |
| --- | --- |
| `Label` · 파일명 | 다른 이름으로 (본 작업을 덮어쓰지 않게) |
| 명령의 맨 끝 | `--cycle-dossiers 4` → **`--help`** |
| `StartCalendarInterval` 항목 | **통째로 지운다** — 예약이 아니라 손으로 한 번만 부릅니다 |
| 로그 경로 | 다른 파일로 (회차 로그와 섞이지 않게) |

```bash

launchctl bootout gui/$(id -u)/<그 라벨>
rm ~/Library/LaunchAgents/<그 이름>.plist
```

### 5.1 🔴 「중단됐다」와 「아예 안 돌았다」를 가르는 법

**새벽에 도는 회차라 이 구별이 대응을 정합니다** — 봐야 할 곳이 서로 다릅니다.

| 회차 로그의 모양 | 무슨 일이 났나 | 어디를 보나 |
| --- | --- | --- |
| 시작 + 종료 | **정상으로 끝났다** (종료 코드가 무엇이든) | 종료 줄의 코드와 멈춘 이유 |
| 🔴 **시작만 있고 종료가 없다** | **중단됐다** — 강제 종료 · 컨테이너 죽음 · 전원 차단 · 예외로 죽음 | 예약 실행의 오류 로그(추적이 찍혀 있으면 예외로 죽은 것) · 도커가 떠 있는지(2절 ③) |
| **그 회차의 줄이 아예 없다** | **시작조차 못 했다** | **트리거 쪽** — 등록 상태 · `PATH` · 토큰 파일 |

🔴 **죽는 프로세스는 아무것도 적을 수 없습니다.** 그래서 중단은 「끝이 없다」로만 판정되고,
그러려면 시작이 미리 적혀 있어야 합니다 — 그것이 이 파일이 있는 이유입니다.

**[주의] 지금 도는 중인 회차도 「시작만 있는」 모양입니다.** 그 구별은 이 파일 밖에 있습니다 —
6절의 컨테이너 목록을 보면 됩니다. **지난** 회차를 볼 때만 중단으로 읽습니다.

### 5.2 한도 비율을 «보정»하는 법 — 모델을 바꾸면 다시 합니다

**분모(한 창의 한도)는 러너가 읽을 수 없습니다.** 응답에 한도·잔량 필드가 없고, 사용률은
**사람의 로그인으로만** 보입니다 — 회차가 쓰는 장기 토큰으로 `/usage` 를 부르면 그 세션의 비용
요약만 나옵니다. 그래서 사람이 재서 넣습니다. **모델을 바꾸면 다시 잽니다.**

1. **호스트에서, 사람의 로그인으로** `claude -p "/usage"` 를 부릅니다. 모델을 부르지 않아
   **비용이 0** 이고, 5시간 창과 주간의 사용률이 나옵니다. 저장소 밖 폴더에서 부릅니다
2. **「직전 측정 → 회차 → 직후 측정」을 스크립트 하나로 묶어** 돌립니다. 그러면 재는 쪽
   세션의 요청이 그 사이에 끼지 않습니다(아래 「관찰자 몫」). 그 스크립트에서 🔴 **장기 토큰은
   회차를 띄우는 명령에만** 넘기고, `/usage` 를 부를 때는 환경에 없게 합니다 — 있으면 그 토큰으로
   인증해 사용률 대신 비용 요약만 나오고 **에러는 안 납니다.** `/usage` 는 표준 입력을 닫고
   (`< /dev/null`) 부릅니다 — 백그라운드에서 입력을 기다리며 멈추지 않게
3. **두 값의 차이가 이 회차가 먹은 창의 비율**입니다
4. 회차 로그의 종료 줄에서 **`tokens_new_total`** 을 읽어(성분을 더한 값이 그 자리에
   함께 적혀 있습니다), 위 비율과 함께 한 창의 토큰 수를 역산해 넣습니다.
   **두 번 재서** 두 역산이 맞는지 봅니다

🔴 **분자는 «새 토큰»입니다 — `tokens_cache_read` 를 더하지 않습니다.**
[실측 2026-09-15] 한때 캐시 읽기도 한도를 먹는다고 보았으나, 두 번 재서 부정했습니다 —
포함해 풀면 두 측정이 **1.8배 어긋나고** 빼고 풀면 **2.4% 안에서 일치**합니다.
근거는 `docs/DESIGN.md` §11.9 입니다.

🔴 **눈으로 읽어 다시 타이핑하지 않습니다.** 이 숫자는 **영구 분모**가 되므로 한 자리만
틀려도 이후 모든 비율이 틀립니다.

🔴 **잰 날짜를 값과 함께 적습니다.** 한도 정책이 바뀌면 그 값이 조용히 틀리므로
**날짜 없는 비율을 내지 않습니다.**

#### 재는 동안 조심할 것 — [실측 2026-09-15 · 2026-09-23]

| 함정 | 무엇이 일어나나 | 어떻게 피하나 |
| --- | --- | --- |
| **분자를 키운다** | `/usage` 의 사용률이 **정수 %** 라, 한 장짜리 회차의 Δ 가 4 %p 면 참값이 3~5 사이이고 그것만으로 창이 **1.7배 벌어집니다** | 한 회차가 **여러 장**을 내게 세웁니다. Δ 가 클수록 이 오차가 묻힙니다 |
| **관찰자 몫** | 재는 사람의 세션도 **같은 창**을 먹습니다. 사용률은 계정 전체 값이라 **다른 세션 · claude.ai · 다른 기기**의 사용도 섞입니다 | `claude -p "/usage"` 는 비용이 0 이라, 전후 측정과 회차를 **스크립트 하나로 묶으면** 재는 쪽 몫이 구간 밖으로 빠집니다. 도는 동안은 **대화도 포함해 Claude 사용을 멈춥니다.** 예전 방식(대화 세션의 `/usage`)은 이 몫이 섞여 창을 «작게» 잡았고 그래서 비율이 늘 크게(안전하게) 나왔지만, **새 방식에는 그 안전 쪽 치우침이 없습니다** |
| **창이 리셋을 가로지른다** | 5시간 창은 «첫 요청»에서 열립니다. 회차 도중에 리셋되면 **Δ 가 음수로 나오면서도 에러가 안 납니다.** [실측 2026-09-23] Opus 한 장은 40 ~ 50분 걸립니다 | 회차 «전» 값을 읽을 때 리셋 예정 시각이 **회차 종료 예상보다 뒤인지** 먼저 봅니다. **가로지른 회차는 보정에 쓰지 않고 다시 잽니다** — 리셋 직전 사용률을 따로 읽어도 그때 돌던 단계의 몫이 어디까지 들어갔는지 알 수 없습니다. [실측 2026-09-23] 한 번 그렇게 걸려 참고로만 남겼습니다 |
| **회차 토큰으로는 사용률이 안 보인다** | 컨테이너 안에서 장기 토큰으로 `/usage` 를 부르면 그 세션의 비용 요약만 나오고 **에러는 안 납니다** | 사용률은 호스트에서 사람의 로그인으로 읽습니다 |
| **「전» 값을 너무 일찍 읽는다** | 리셋 직후에 읽으면 그 뒤 사람이 쓴 몫이 **전부 Δ 에 들어옵니다** | 회차 **시작 직전**에 읽습니다 |

> **한 장이 창의 몇 %인지는 이미 실측돼 있습니다** — 약 23% 였고(§11.9), 모델을 바꾼 뒤에는
> 25.6% · 27.5% 입니다(§11.15). 다시 재는 것은 **모델을 바꿨을 때**와 그 값이 의심스러울
> 때이며, 그때도 **한도 정책이 바뀌었는지**부터 봅니다.

🔴 **이 값으로도 「한도가 몇 % 남았나」는 알 수 없습니다.** 창이 언제 시작됐는지를
파이프라인이 모르기 때문입니다. 잔량이 궁금하면 `/usage` 를 직접 봅니다.

## 6. 🔴 기계가 «안 막는» 것 — 손으로 돌리기 전에 본다

**예약된 회차가 도는 동안 호스트에서 직접 회차를 돌리면 막히지 않습니다.**

동시 실행을 막는 잠금은 커널이 쥐고 있어 프로세스가 어떻게 죽든 풀립니다. 그 성질이
「컨테이너가 죽으면 파이프라인이 무인 상태로 정지」하던 버그를 고쳤지만, 대신
**그 잠금은 컨테이너와 호스트 사이를 넘지 못합니다.** 컨테이너끼리는 정상으로 막힙니다.

겹치면 **둘이 같은 실행 폴더와 같은 후보 목록을 번갈아 쓰고, 한쪽의 갱신이 예외도 로그도
없이 사라집니다.**

**확인 수단은 있습니다 — 잠금이 아니라 컨테이너 목록입니다.**

```bash
docker ps
```

운용 경로가 컨테이너 하나이므로, **목록에 이 프로젝트의 컨테이너가 없으면 예약 회차가
지금 돌고 있지 않다는 뜻**입니다. 손으로 돌리기 전에 이것만 봅니다.

> **이미지 이름으로 거르지 않는 편이 안전합니다.** 실행 스크립트가 이미지 이름을 환경변수로
> 덮어쓸 수 있어서, 이름을 박아 거르면 **덮어쓴 날 조용히 「안 돌고 있음」으로 보입니다.**

> **왜 코드로 안 막았나**: 시각 기준 신호는 「죽인 뒤 5분 만에 재실행」과 「5분째 정상
> 실행 중」을 구별하지 못해 이미 한 번 기각된 수단이고, 되살리면 **고쳤던 정지 버그가
> 그 길로 돌아옵니다.** 러너가 컨테이너 목록을 직접 보게 하면 **컨테이너 «안»에서는 그
> 명령이 없어 운용 경로에서 되레 깨집니다.** 그래서 못 막는 자리를 여기 적는 쪽을 택했습니다.

## 8. 멈추거나 고칠 때

### 8.1 예약을 끈다 — 🔴 끄기는 «두 동작»입니다

```bash
./scripts/trigger.sh off      # 끄고, 정말 꺼졌는지 검증까지 합니다
./scripts/trigger.sh status   # 「지금」과 「재부팅 후」를 갈라 보여줍니다
```

**`launchctl bootout` 만 걸면 재부팅에서 되살아납니다.** 작업 정의 파일이
`~/Library/LaunchAgents/` 에 남아 있으면 다음 로그인 때 launchd 가 다시 올립니다.

| 조작 | 지금 세션 | 재부팅 후 |
| --- | --- | --- |
| `bootout` 만 | 내려감 | 🔴 **다시 올라와 돕니다** |
| `disable` 만 | 🔴 **계속 돕니다** | 안 올라옴 |
| **`disable` + `bootout`** | 내려감 | 안 올라옴 |

**[실측] 2026-09-21** — 더미 LaunchAgent 로 쟀습니다. `disable` 만 건 서비스는
`kickstart` 가 그대로 실행됐고(로그 1줄 → 2줄), 둘 다 건 뒤에는 `rc=113` 으로 서비스를
찾지 못했습니다. `disable` 상태는 `/var/db/com.apple.xpc.launchd/disabled.<uid>.plist`
에 기록되므로 재부팅을 넘습니다. 자세한 경위는 [DESIGN.md](DESIGN.md) §11.13 에 있습니다.

> 🔴 **`launchctl list` 로 꺼졌는지 판정하지 마세요.** `disabled` 인 서비스도 그대로
> 보여줍니다. 실제로 그 출력만 보고 「내려갔다」고 판정했다가 **사흘간 회차가 도는 것을
> 놓쳤습니다.** 그래서 `status` 가 로드 여부와 disabled 여부를 **따로** 냅니다 —
> 특히 **「지금은 안 도는데 재부팅하면 도는」 조합**을 못 박아 경고합니다.
>
> 🔴 **도는 중인 회차가 있으면 `off` 가 경고합니다.** 내리면 그 회차가 끊길 수 있고,
> 끊긴 회차는 `runs/cycles.jsonl` 에 종료 줄을 남기지 못해 **5.1 의 「시작만 있고 종료가
> 없다」로 보입니다** — 전원 차단과 구별되지 않습니다. 경고만 하고 막지는 않습니다.

**스크립트를 못 쓰는 상황**(다른 기계·셸만 있는 복구)에서는 직접 두 줄을 겁니다.
되살릴 때는 **`enable` 이 `bootstrap` 보다 먼저**여야 합니다 — 순서가 반대면
`Bootstrap failed: 5: Input/output error` 로 거부됩니다.

```bash
# 끈다
launchctl disable gui/$(id -u)/local.research-lab.cycle
launchctl bootout  gui/$(id -u)/local.research-lab.cycle

# 켠다
launchctl enable    gui/$(id -u)/local.research-lab.cycle
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.research-lab.cycle.plist
```

### 8.2 나머지를 되돌린다

```bash
# 절전 해제 예약을 지운다
sudo pmset repeat cancel

# 엔진 자동 시작을 되돌린다 (3.0절)
brew services stop colima
```

**둘 다 `trigger.sh` 가 건드리지 않습니다.** 앞은 `sudo` 가 필요해 사람 몫이고,
뒤는 토큰을 쓰지 않으면서 다른 작업의 도커까지 멈추기 때문입니다.

### 8.3 작업 정의 파일을 고친 뒤

**`bootout` → `bootstrap` 순으로 다시 올립니다.** 고치기만 하면 이미 올라간 정의가
그대로 돕니다. `./scripts/trigger.sh off` 다음에 `on` 을 부르면 같은 일을 하면서
**disabled 기록까지 정리**됩니다.

> 🔴 **진입점 파일 이름이 바뀌면 컨테이너 이미지를 다시 빌드해야 합니다.**
> 소스는 호스트 폴더를 그대로 물려 쓰므로 평소에는 빌드가 필요 없는데, **진입점만
> 이미지에 구워져 있어서** 안 빌드하면 「그런 파일이 없다」로 회차가 죽습니다.
> 빌드 명령은 [COMMANDS.md](COMMANDS.md) 에 있습니다.
>
> 🔴 **`Dockerfile` 이 바뀌어도 다시 빌드합니다 — 특히 Claude Code 버전 고정.** 러너가 부르는
> 모델은 코드(호출 계층)에 고정돼 있고 소스는 그대로 물려 쓰는데, 그 모델을 받는 CLI 는
> **이미지에 구워져 있습니다.** 코드만 새것이고 이미지가 옛것이면 모든 호출이 「이 CLI 버전은
> 그 모델을 지원하지 않는다」는 400 으로 거부됩니다. 그 문구는 실패 분류표에 없어 「그 외」로
> 떨어지므로 **재시도를 반복하다 같은 단계가 3회차 연속 막히면 멀쩡한 후보가 원장에 `- [!]` 로
> 막히고**, 그 사유는 원인을 가리키지 않습니다. 실측과 고정한 이유는 [DESIGN.md](DESIGN.md) §11.15 에
> 있습니다.
