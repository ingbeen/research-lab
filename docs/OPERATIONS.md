# 운용 — 트리거를 붙이고, 기계를 옮긴다

> 이 문서는 **그 기계의 OS 설정**을 다룹니다. 저장소의 실행 명령어와 그 옵션의 뜻은
> [COMMANDS.md](COMMANDS.md) 가 단일 SoT 이며 여기에 복제하지 않습니다.
>
> **등록과 설정은 사람이 직접 합니다.** 아래 명령은 제가 대신 실행하지 않고,
> 무엇이 이 기계에 설치·등록되는지를 쓰는 사람이 통제합니다. 등록된 뒤의
> **읽기 전용 확인**만 함께 봅니다.

---

## 1. 운용기는 mac 입니다 (2026-09-14 결정)

| 후보 | 붙이는 것 |
| --- | --- |
| **mac (채택)** | `launchd` + `pmset` 절전 해제 + `caffeinate` + **엔진 자동 시작** |
| WSL | Windows 작업 스케줄러의 「절전 모드 해제」 옵션 + `wsl.exe -- docker run …` |

**근거**: 파이프라인을 지은 뒤 세 단계가 전부 mac 에서 돌았고, 원래 설계도 「최종 운용은
mac 한 대」였습니다. 컨테이너로 싸 둔 덕에 **옮길 때 바뀌는 것이 트리거뿐**이라는 전제는
그대로이며, 그 전제를 실제로 쓰는 자리가 아래 7절입니다.

## 2. 착수 전 확인 — 읽기 전용

셋 다 **없으면 회차가 시작 자체를 거부**하거나 조용히 안 돕니다.

```bash
# ① 무인 실행용 장기 토큰이 있는가.
#    [주의] 환경변수로 «재지 않습니다» — 토큰은 파일에 있고 셸에 export 돼 있지 않습니다.
#    자리는 루트 CLAUDE.md 가 정한 저장소 밖 키 폴더이며, 없으면 'claude setup-token' 으로 한 번만 발급합니다
[ -s ~/.claude/keys/research-lab-oauth-token ] && echo "토큰 파일 있음" || echo "토큰 파일 없음"

# ② API 키가 «없어야» 한다. 있으면 구독 대신 API 로 과금된다
[ -n "${ANTHROPIC_API_KEY+x}" ] && echo "[위험] API 키가 설정돼 있다" || echo "API 키 없음 (정상)"

# ③ 컨테이너 런타임이 떠 있는가
docker info >/dev/null 2>&1 && echo "도커 정상" || echo "도커가 안 떠 있다"
```

🔴 **① 을 환경변수로 재면 「없음」이 나오는데 그것이 「발급 안 됨」이 아닙니다.** 토큰은
파일로만 두고 예약 작업이 실행 시점에 읽어 갑니다(3.1절) — 그래야 **사본이 한 벌**이고
토큰을 새로 발급할 때 작업 정의 파일을 고칠 일이 없습니다.

🔴 **③ 이 이 기계의 약한 고리입니다.** 도커 엔진이 VM 위에 있어서 **재부팅하면 엔진이
내려가고, 다시 띄우기 전까지 예약 회차가 매번 실패합니다.** 종료 코드로는 그냥 실패로
보일 뿐 「도커가 안 떠 있다」로는 안 보입니다.

> **[실측 2026-09-14] 이 기계의 엔진은 로그인 시 «자동으로 뜨지 않았습니다».**
> 서비스로 등록돼 있지 않고, 사용자·시스템 영역의 자동 실행 목록 어디에도 항목이 없었으며,
> **엔진 프로세스의 시작 시각이 부팅 시각보다 열나흘 늦었습니다**(사람이 손으로 띄운 것).
> 그때까지 돌던 이유는 **재부팅이 없었기 때문**입니다 — 무인 운용의 전제로 삼을 수 없어
> 아래 3.0 절에서 자동 시작을 등록합니다.

## 3. 트리거 등록 — 사용자가 실행합니다

예약 시각은 **매일 01:00 (KST)** 입니다. 근거는 사용 한도가 「첫 프롬프트부터」 5시간
창으로 돌기 때문이고, 낮에 직접 쓰는 시간대와 겹치지 않는 쪽이 유리합니다.

### 3.0 컨테이너 엔진을 «로그인과 같이» 띄운다 (2026-09-14 결정)

2절 ③ 의 실측대로 엔진은 스스로 뜨지 않으므로 **서비스로 등록**합니다.
homebrew 로 깐 엔진이면 한 줄입니다.

```bash
brew services start colima
brew services list          # 등록 확인 — 상태가 'started' 여야 한다
```

**예약 작업과 «같은 수명»을 갖는 것이 이 선택의 이유입니다.** 아래에서 만드는 작업도
사용자 로그인 세션에 등록되므로, 엔진을 같은 자리에 두면 **둘이 함께 뜨고 함께 내려갑니다** —
「작업은 떴는데 엔진이 없어 매일 실패하는」 어긋남이 구조적으로 안 생깁니다.

| 탈락안 | 왜 버리나 |
| --- | --- |
| **회차를 띄울 때 함께 엔진을 시작한다** | 01:00 에 **VM 부팅이 실패하는 모드가 하나 늘고**, 그 코드가 실행 스크립트에 들어가면 이 기계·이 엔진 전용이 되어 **7절이 약속한 「옮길 때 바뀌는 것은 트리거뿐」이 깨집니다** |
| 그대로 두고 재부팅한 날 손으로 띄운다 | 무인 운용에는 그것을 기억할 사람이 없습니다. **실패가 「엔진이 없다」로 안 보이는 것**이 2절 ③ 의 내용입니다 |

🔴 **등록 직후의 「stopped」를 고장으로 읽지 마세요 — 그리고 「등록됐다」로도 읽지 마세요.**
이미 손으로 띄운 엔진이 돌고 있으면 서비스는 뜰 때마다 **「이미 돌고 있음」으로 즉시 끝나고
10초마다 다시 뜨는 공회전**이 됩니다. 목록에는 `stopped` 으로 보이고 엔진은 정상이라,
**둘 중 무엇이 VM 을 쥐고 있는지가 목록에 안 나옵니다.**

**갈라 보는 법은 하나입니다 — 손으로 띄운 것을 내리고 서비스가 스스로 올리는지 봅니다.**
그 조합이 **깨끗한 부팅과 같은 조건**입니다.

```bash
colima stop                 # 손으로 띄운 것을 내린다
brew services list          # 상태가 started 로 바뀌어야 한다
docker info                 # 조금 기다린 뒤 정상이어야 한다
```

> **[실측 2026-09-15] 이 기계에서는 24초에 복귀했습니다** — 사람 손 0.
> 그 전까지는 위 공회전 상태였고, **목록만 보고 넘겼다면 그대로 굳었을 것입니다.**

### 3.1 작업 정의 파일을 만든다

`~/Library/LaunchAgents/local.research-lab.cycle.plist` 로 저장합니다.
**저장소 «밖»입니다** — 이 저장소는 PUBLIC 입니다.

🔴 **토큰을 이 파일에 «적지 않습니다».** 실행 시점에 키 파일에서 읽어 넘깁니다.
적으면 자격증명 사본이 두 벌이 되어 **토큰을 새로 발급할 때마다 두 곳을 고쳐야 하고,
한 곳을 잊으면 예약 회차가 만료된 토큰으로 조용히 실패합니다.**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>local.research-lab.cycle</string>

  <key>ProgramArguments</key>
  <array>
    <!-- 토큰은 키 파일에서 실행 시점에 읽는다. 이 파일에는 자격증명이 들어가지 않는다.
         로그인 셸로 열지 않는다('-lc' 금지) — 프로필이 ANTHROPIC_API_KEY 를 들여올 수 있다.
         caffeinate 로 감싼다. 회차가 길어질 수 있어 도는 중에 다시 잠들면 안 된다 -->
    <string>/bin/sh</string>
    <string>-c</string>
    <string>export CLAUDE_CODE_OAUTH_TOKEN="$(cat /Users/사용자이름/.claude/keys/research-lab-oauth-token)"; exec /usr/bin/caffeinate -i /Users/사용자이름/Workspace/research-lab/docker/run.sh --cycle-budget-usd 10</string>
  </array>

  <key>StartCalendarInterval</key>
  <dict>
    <key>Hour</key><integer>1</integer>
    <key>Minute</key><integer>0</integer>
  </dict>

  <key>EnvironmentVariables</key>
  <dict>
    <!-- launchd 는 로그인 셸의 환경을 «물려받지 않는다». 넘길 것을 여기 적어야 한다 -->
    <key>PATH</key>
    <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
  </dict>

  <key>StandardOutPath</key>
  <string>/Users/사용자이름/Library/Logs/research-lab/cycle.out.log</string>
  <key>StandardErrorPath</key>
  <string>/Users/사용자이름/Library/Logs/research-lab/cycle.err.log</string>
</dict>
</plist>
```

🔴 **여기서 조용히 틀어지는 자리가 셋입니다.**

| 자리 | 안 하면 |
| --- | --- |
| **`PATH` 를 적는다** | launchd 의 기본 경로에는 `docker` 가 없습니다. 회차가 「명령을 못 찾음」으로 끝나는데, **로그를 안 보면 그냥 안 돈 것처럼 보입니다** |
| **`--cycle-budget-usd` 를 «명시»한다** | 기본값에 기대면 나중에 그 기본값을 고치는 날 **예약 회차의 동작이 조용히 달라집니다** |
| **`ANTHROPIC_API_KEY` 를 «안» 적는다** | 적으면 그 순간 구독 대신 API 로 과금됩니다. launchd 가 환경을 안 물려받는 것이 여기서는 **안전판**이니 그대로 둡니다 |

**로그 폴더를 미리 만들고, 좁혀야 할 권한은 «키 파일» 쪽인지 확인합니다.**
작업 정의 파일에는 자격증명이 없습니다.

```bash
mkdir -p ~/Library/Logs/research-lab
ls -l ~/.claude/keys/research-lab-oauth-token   # 권한이 600 이어야 한다
```

### 3.3 잠든 기계를 깨운다

**예약 장치는 기계를 깨우지 않습니다** — 그래서 예약 시각보다 조금 앞서 따로 깨웁니다.
**이 한 줄만 `sudo` 가 필요합니다.**

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 00:55:00
```

🔴 **「그 시각에 못 돈다」와 「아예 안 돈다」를 헷갈리지 마세요.** 잠든 동안 시각이 지나가면
회차는 **그 시각에** 못 돌고, **깨어난 뒤에 늦게** 도는 것으로 알려져 있습니다.
**[미검증]** 이 기계에서 그런지는 안 쟀습니다.

**이 구별이 내일 결과를 읽는 방식을 바꿉니다.**

| 회차가 돈 시각 | 읽는 법 |
| --- | --- |
| 예약 시각 그대로 | **절전 해제가 깨웠다** — 위 [미검증]이 「깨운다」로 닫힌다 |
| 사람이 기계를 쓰기 시작한 시각 | **깨우지 못했고, 예약 장치가 늦게 따라잡았다** — 무인 운용이 아니라 「사람을 기다린 운용」이다 |
| 안 돌았다 | 둘 다 아니다. 로그와 종료 코드부터 본다 |

> **[미검증] 「절전 해제가 실제로 이 기계를 깨우는가」는 아직 안 쟀습니다.**
> 설계가 처음부터 재기로 하고 미뤄 둔 항목이며, **추론으로 넘기면 안 되는 자리**입니다 —
> 이 저장소는 권한 비트를 추론했다가 틀린 적이 있고, **작업 환경 목록을 보고 `HOME` 이
> 없다고 판정했다 틀린 적도 있습니다**(4절). 첫 예약 회차가 그 답입니다.

## 4. 등록 뒤 확인 — 읽기 전용

```bash
# 등록됐나
launchctl print gui/$(id -u)/local.research-lab.cycle | head -20

# 엔진도 함께 뜨게 돼 있나 (3.0절)
brew services list

# 다음 절전 해제 예약
pmset -g sched

# 지난 회차가 어떻게 끝났나
tail -40 ~/Library/Logs/research-lab/cycle.err.log
```

🔴 **위 명령이 찍는 환경 목록을 «실행 환경»으로 읽지 마세요.** `HOME` 처럼 실행 시점에야
들어오는 값이 목록에 없습니다. **[실측 2026-09-15]** 목록에 없어서 「HOME 이 없다」고
판정했는데 실제로는 들어왔습니다 — 나열된 것으로 판정하면 틀립니다. 재는 법이 아래에 있습니다.

### 4.1 예약 실행 경로를 «$0 로» 찔러 본다

**회차 하나는 $2~5 인데 이 확인은 0 입니다.** 진입점의 도움말만 출력하게 하면
에이전트를 한 번도 부르지 않으면서 **토큰 파일 읽기 · `PATH` · 엔진 소켓 · 컨테이너
진입점**이 한 줄로 이어지는지 드러납니다. **새 기계로 옮길 때마다 값이 있습니다** —
배선이 깨졌다면 돈을 쓰기 «전»에 나옵니다.

3.1 절의 작업 정의를 복사해 **네 곳만** 바꿉니다.

| 바꿀 것 | 무엇으로 |
| --- | --- |
| `Label` · 파일명 | 다른 이름으로 (본 작업을 덮어쓰지 않게) |
| 명령의 맨 끝 | `--cycle-budget-usd 10` → **`--help`** |
| `StartCalendarInterval` 항목 | **통째로 지운다** — 예약이 아니라 손으로 한 번만 부릅니다 |
| 로그 경로 | 다른 파일로 (회차 로그와 섞이지 않게) |

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/<그 이름>.plist
launchctl kickstart -w gui/$(id -u)/<그 라벨>
cat ~/Library/Logs/research-lab/<그 로그>          # 도움말이 찍혔으면 배선이 성립한다

# 끝나면 걷어낸다 — 남겨 두면 다음 사람이 이게 무엇인지 되짚어야 한다
launchctl bootout gui/$(id -u)/<그 라벨>
rm ~/Library/LaunchAgents/<그 이름>.plist
```

### 5.1 🔴 「중단됐다」와 「아예 안 돌았다」를 가르는 법

**새벽에 도는 회차라 이 구별이 대응을 정합니다** — 봐야 할 곳이 서로 다릅니다.

| 회차 로그의 모양 | 무슨 일이 났나 | 어디를 보나 |
| --- | --- | --- |
| 시작 + 종료 | **정상으로 끝났다** (종료 코드가 무엇이든) | 종료 줄의 코드와 멈춘 이유 |
| 🔴 **시작만 있고 종료가 없다** | **중단됐다** — 강제 종료 · 컨테이너 죽음 · 전원 차단 · 예외로 죽음 | 예약 실행의 오류 로그(추적이 찍혀 있으면 예외로 죽은 것) · 도커가 떠 있는지(2절 ③) |
| **그 회차의 줄이 아예 없다** | **시작조차 못 했다** | **트리거 쪽** — 등록 상태 · `PATH` · 토큰 파일 |

🔴 **죽는 프로세스는 아무것도 적을 수 없습니다.** 그래서 중단은 「끝이 없다」로만 판정되고,
그러려면 시작이 미리 적혀 있어야 합니다 — 그것이 이 파일이 있는 이유입니다.

**[주의] 지금 도는 중인 회차도 「시작만 있는」 모양입니다.** 그 구별은 이 파일 밖에 있습니다 —
6절의 컨테이너 목록을 보면 됩니다. **지난** 회차를 볼 때만 중단으로 읽습니다.

### 5.2 한도 비율을 «보정»하는 법 — 한 번만 합니다

**분모(한 창의 한도)는 프로그램으로 읽을 수 없습니다.** CLI 에 사용량을 내주는 명령이 없고
응답에도 한도·잔량 필드가 없어, 한도 신호는 **부딪혔을 때의 「소진 + 리셋 시각」 문구**
하나뿐입니다. 그래서 사람이 한 번 재서 넣습니다.

1. 회차 «전»에 대화 세션에서 `/usage` 로 현재 사용률을 적어 둡니다
2. 회차를 돌립니다 — **근거 문서 한 장만 내게 하려면 회차 예산을 작게 줍니다.**
   첫 실행 폴더는 예산과 무관하게 한 번 돌고, 판정은 그 «뒤»에 걸립니다
3. 회차 «후»에 `/usage` 를 다시 봅니다. **그 차이가 이 회차가 먹은 창의 비율**입니다
4. 회차 로그의 종료 줄에서 **`tokens_limit_total`** 을 읽어(성분 넷의 합이 그 자리에
   함께 적혀 있습니다), 위 비율과 함께 한 창의 토큰 수를 역산해 넣습니다

🔴 **그 합을 손으로 더하지 않습니다.** 성분 넷을 눈으로 읽어 다시 타이핑한 값은
근거물이 아니고, 이 숫자는 **영구 분모**가 되므로 한 자리만 틀려도 이후 모든 비율이 틀립니다.

🔴 **잰 날짜를 값과 함께 적습니다.** 한도 정책이 바뀌면 그 값이 조용히 틀리므로
**날짜 없는 비율을 내지 않습니다.**

🔴 **이 값으로도 「한도가 몇 % 남았나」는 알 수 없습니다.** 창이 언제 시작됐는지를
파이프라인이 모르기 때문입니다. 잔량이 궁금하면 `/usage` 를 직접 봅니다.

## 6. 🔴 기계가 «안 막는» 것 — 손으로 돌리기 전에 본다

**예약된 회차가 도는 동안 호스트에서 직접 회차를 돌리면 막히지 않습니다.**

동시 실행을 막는 잠금은 커널이 쥐고 있어 프로세스가 어떻게 죽든 풀립니다. 그 성질이
「컨테이너가 죽으면 파이프라인이 무인 상태로 정지」하던 버그를 고쳤지만, 대신
**그 잠금은 컨테이너와 호스트 사이를 넘지 못합니다.** 컨테이너끼리는 정상으로 막힙니다.

겹치면 **둘이 같은 실행 폴더와 같은 후보 목록을 번갈아 쓰고, 한쪽의 갱신이 예외도 로그도
없이 사라집니다.**

**확인 수단은 있습니다 — 잠금이 아니라 컨테이너 목록입니다.**

```bash
docker ps
```

운용 경로가 컨테이너 하나이므로, **목록에 이 프로젝트의 컨테이너가 없으면 예약 회차가
지금 돌고 있지 않다는 뜻**입니다. 손으로 돌리기 전에 이것만 봅니다.

> **이미지 이름으로 거르지 않는 편이 안전합니다.** 실행 스크립트가 이미지 이름을 환경변수로
> 덮어쓸 수 있어서, 이름을 박아 거르면 **덮어쓴 날 조용히 「안 돌고 있음」으로 보입니다.**

> **왜 코드로 안 막았나**: 시각 기준 신호는 「죽인 뒤 5분 만에 재실행」과 「5분째 정상
> 실행 중」을 구별하지 못해 이미 한 번 기각된 수단이고, 되살리면 **고쳤던 정지 버그가
> 그 길로 돌아옵니다.** 러너가 컨테이너 목록을 직접 보게 하면 **컨테이너 «안»에서는 그
> 명령이 없어 운용 경로에서 되레 깨집니다.** 그래서 못 막는 자리를 여기 적는 쪽을 택했습니다.

## 7. 다른 기계로 옮길 때 — 바뀌는 것과 안 바뀌는 것

| 안 바뀐다 | 왜 |
| --- | --- |
| 저장소 · 컨테이너 이미지 정의 · 의존성 잠금 | 베이스 이미지가 여러 아키텍처를 다 가지고 있습니다 |
| 컨테이너 «안» 경로 | 고정돼 있고 호스트 경로는 바깥에서 주입합니다 |
| 실행 사용자 지정 | 파일 공유 계층이 사용자 번호를 호스트 사용자로 옮겨 줘서, 번호가 달라도 그대로 둡니다 |
| 산출물이 생기는 자리 | 저장소 폴더를 그대로 물려 쓰므로 컨테이너 안에 상태가 남지 않습니다 |

| 바뀐다 | 무엇을 한다 |
| --- | --- |
| **트리거** | 이 문서 3절을 그 기계의 방식으로 다시 합니다 (WSL 이면 Windows 작업 스케줄러 + 「절전 모드 해제」) |
| **절전 해제** | 기계마다 수단이 다르고, **답도 다릅니다 — 그 기계에서 다시 재야 합니다** |
| **컨테이너 엔진 자동 시작** | 엔진과 OS 마다 수단이 다릅니다. 3.0 절을 그 기계의 방식으로 다시 하고, **「자동으로 뜨는가」를 그 기계에서 다시 잽니다** — 이 기계에서는 「아니오」였습니다(2절 ③) |
| 에이전트의 홈 폴더 | 저장소 밖 호스트 폴더라 기계를 따라오지 않습니다. 잃는 것은 없습니다 — 되짚을 기록은 저장소 안에 쌓입니다 |
| 토큰 | 그 기계에서 새로 발급합니다 |

**옮긴 뒤 첫 할 일은 품질 검증 한 번입니다** — 명령은 [COMMANDS.md](COMMANDS.md) 에 있습니다.
**트리거를 붙인 뒤에는 4.1 의 찔러보기를 한 번 돕니다** — 그 기계에서 배선이 이어지는지를
**돈을 쓰기 전에** 가르는 자리입니다.
WSL 에서 돌리면 **잠금이 그 파일 시스템에서 표준대로 도는지**라는 남은 [미검증] 항목도
함께 닫힙니다. 저장소를 Windows 드라이브가 아니라 리눅스 파일 시스템에 두는 것이 전제입니다.

## 8. 멈추거나 고칠 때

```bash
# 잠시 끈다
launchctl bootout gui/$(id -u)/local.research-lab.cycle

# 절전 해제 예약을 지운다
sudo pmset repeat cancel

# 엔진 자동 시작을 되돌린다 (3.0절)
brew services stop colima
```

**작업 정의 파일을 고친 뒤에는 `bootout` → `bootstrap` 순으로 다시 올립니다.**
고치기만 하면 이미 올라간 정의가 그대로 돕니다.

> 🔴 **진입점 파일 이름이 바뀌면 컨테이너 이미지를 다시 빌드해야 합니다.**
> 소스는 호스트 폴더를 그대로 물려 쓰므로 평소에는 빌드가 필요 없는데, **진입점만
> 이미지에 구워져 있어서** 안 빌드하면 「그런 파일이 없다」로 회차가 죽습니다.
> 빌드 명령은 [COMMANDS.md](COMMANDS.md) 에 있습니다.
