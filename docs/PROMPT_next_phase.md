## 0. 🔴 [일회용] 이 블록을 «먼저» 처리하고, 끝나면 이 블록을 지운다

**이 문서에서 유일하게 수명이 있는 자리입니다.** 바로 아래 절이 「이 문서는 낡지 않는다」고
말하는 것과 어긋나 보이지만, **처리하면 스스로 사라지므로** 그 성질이 유지됩니다.

### 무엇을 — 두 기계의 Poetry 버전을 맞춘다

맥은 Poetry **2.4.1**, WSL 은 **1.8.2** 입니다. `poetry.lock` 은 1.8.2 가 만든
`lock-version = "2.0"` 이고 **읽는 것은 양쪽 다 됩니다.** 갈리는 것은 **쓰는 쪽**이라
**의존성을 하나라도 추가하는 날** 터집니다. 왜 「맞춘다」로 정했는지와 탈락안은
[DESIGN.md](DESIGN.md) §11.3 에 있습니다.

**절차**

1. **이 기계가 WSL 인지 본다.**

   ```bash
   grep -qi microsoft /proc/sys/kernel/osrelease 2>/dev/null && echo "WSL" || echo "WSL 아님"
   ```

2. 🔴 **WSL 이 «아니면» 아무것도 하지 않고 §1 로 넘어간다. 이 블록도 지우지 않는다.**
   여기서 지우면 WSL 이 이 지시를 영영 못 받습니다.

3. **WSL 이면** 지금 버전과 설치 방식을 확인한다 — 업그레이드 명령이 그것에 따라 갈립니다.

   ```bash
   poetry --version; command -v poetry; ls -l "$(command -v poetry)"
   ```

4. **확인한 설치 방식에 맞는 업그레이드 명령을 «사용자에게 제시하고 기다린다».**
   환경 설치는 사용자가 직접 합니다 — 대신 실행하지 않습니다.

5. 업그레이드 뒤 둘 다 통과해야 끝입니다.

   ```bash
   poetry --version      # 2.x 여야 한다
   poetry check --lock   # exit=0 이어야 한다
   ```

   `check --lock` 이 실패하면 **lock 을 다시 만들지 말고 멈춰 사용자에게 알립니다** —
   그 실패가 곧 「1.8.2 가 만든 lock 을 2.x 가 못 읽는다」는 [미검증] 항목의 답입니다.

6. 🔴 **통과했으면 이 §0 블록을 통째로 지웁니다.** 남겨 두면 다음 세션이 또 확인합니다.

## 2. 무엇을 할 단계인지 정한다

**[DESIGN.md](DESIGN.md) §10 의 로드맵 표에서 «아직 안 된 첫 줄»** 이 이번 단계입니다.
그 줄의 **「검증 방법」 칸이 곧 그 단계의 완료 조건**입니다 — 그것을 계획서의 DoD 로 옮깁니다.

**§10.1 에서 그 Phase 가 맡기로 한 개선거리를 같이 봅니다.** 거기 적힌 것은 「나중에」가
아니라 **그 Phase 의 일**입니다.

## 3. 계획서를 쓴다

**전역 `/impl-plan` 스킬이 절차의 SoT 입니다.** 그대로 따릅니다.

- 파일: `docs/plans/PLAN_<short_name>.md`
- 이 저장소의 값(검증 명령 · 근거 승격 목적지 · 커밋 기능명)은 **루트 `CLAUDE.md` 의
  「계획서 규약 — 이 프로젝트의 설정」** 절에 있습니다
- **코드를 고치기 전에 계획서를 승인받습니다.** 훅이 강제합니다

## 4. 이 저장소에서 특히 지킬 것

### 🔴 기계가 지키게 한다

**프롬프트로 지시한 규율은 형식적으로만 지켜집니다.** 이 저장소에서 실제로 세 번 확인됐습니다 —
「다른 말 없이 JSON 만」이라 적었는데 코드펜스로 감쌌고, 검색어를 「3회 이상」이라 적었는데
검사가 없어 아무도 안 봤고, 스킬이 「러너가 검사한다」고 적었는데 **그 검사가 없었습니다.**

> **빠지면 치명적인 것은 러너·게이트가 검사하게 만듭니다.** 문서에 적는 것으로 끝내지 않습니다.

### 🔴 모를 때 안전한 쪽으로 떨어뜨리고 «원문»을 남긴다

실패 분류표가 **세 번 다 빗나갔지만**(인증·예산·한도) 셋 다 복구됐습니다 —
원문을 통째로 남겨 뒀기 때문입니다. 새로 만드는 분류·게이트·판정도 같게 짭니다.

### 🔴 산출물(dossier)은 다른 문서를 가리키지 않는다

**1순위 제약입니다.** 저장소 밖으로 나가면 포인터가 전부 죽습니다.
「그 저장소 규약대로」가 아니라 **적용한 기준 자체를** dossier 안에 적습니다.

### 🔴 한 줄 주장은 «파라미터로 채울 수 있는» 것만

판정 기준은 **「값을 하나 채우면 재는 절차가 확정되는가」** 입니다.
**「숫자가 들어 있는가」가 아닙니다** — 「크게 상회」·「짧은 기간」은 **격자로 받으면 재집니다.**
못 재는 것은 축 자체가 없는 말(「옥석을 가려」)과 판정 시점에 모르는 값(「**미래** 저점」)입니다.

자세한 것은 루트 `CLAUDE.md` 의 해당 절과 [DESIGN.md](DESIGN.md) §10.1 A 에 있습니다.

> **이 기준은 2026-09-12 에 한 번 뒤집혔습니다.** 예전 기준(「숫자가 없으면 기각」)으로
> 진짜 원장을 재 보니 **남은 후보 13개 중 12개가 죽었습니다.** 되돌리려 한다면
> 그 수치를 먼저 보세요 — §10.1 A 에 있습니다.

### 이 저장소는 PUBLIC 이고 에이전트가 무인으로 씁니다

자격증명은 어떤 형태로도 들어오지 않습니다. 개인을 특정하는 정보도 적지 않습니다.

## 6. 끝낼 때

`/impl-plan` 의 Done 조건을 따릅니다. 그중 **기계가 검사하지 않는 것 하나**를 특히 챙깁니다.

> **근거 승격** — 계획서는 주기적으로 전부 삭제됩니다.
> **「이 계획서를 지금 지워도 잃는 것이 없는가?」** 아니라면 아직 옮길 것이 남았습니다.
> 옮기는 것은 결론뿐 아니라 **근거**입니다 — 「값이 X다」가 아니라 「왜 X인가」.
> 목적지는 루트 `CLAUDE.md` 의 「근거 승격 목적지」 표에 있습니다.

그리고 **로드맵 표와 §10.1 을 갱신합니다** — 끝낸 줄에 완료 표시를 하고,
이번에 새로 드러난 개선거리를 §10.1 에 **어느 Phase 가 맡을지와 함께** 적습니다.
적어 두지 않으면 「나중에」는 영영 오지 않습니다.

> 🔴 **§10.1 은 «머리의 표»와 «본문» 두 곳입니다.** 본문만 고치고 표를 두면
> 다음 세션이 표만 보고 자기 몫을 놓칩니다 — 그 표를 그러라고 만들었기 때문입니다.

**끝낸 항목의 본문은 지우지 않습니다.** 거기 적힌 것은 「무엇을 했나」가 아니라
**「왜 그 기준이어야 하나」**이고, 그것이 없으면 다음 사람이 되돌리려 할 때 근거가 없습니다.
대신 제목에 완료 표시를 달고 표의 상태만 바꿉니다.
