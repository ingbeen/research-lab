# INDEX — 문서 지도

> 이 저장소에 무엇이 어디 있고 언제 읽어야 하는지의 **단일 지도**입니다.
> 자동으로 로드되지 않는 문서를 찾을 때 여기를 봅니다.
>
> **문서를 추가·삭제·이동하면 이 파일을 함께 고칩니다.**
> `tests/test_index.py` 가 실제 파일 목록과 대조해 검사하므로, 안 고치면 `validate_project.py` 가 실패합니다.

## 1. 처음 온 세션이 읽을 순서

**진입 순서는 [../CLAUDE.md](../CLAUDE.md) 의 「세션 시작 규칙」이 정합니다.**
그 문서는 항상 자동 로드되므로 순서를 여기에 **복제하지 않습니다** — 두 벌이 되면
한쪽이 낡고, 어느 쪽이 현재인지 매번 판별해야 합니다.

**이 지도는 「그 순서에 없는 문서를 찾을 때」 봅니다.**

> **진행 상태 문서와 인계 문서를 두지 않습니다.** 무엇이 끝났는지는 git 이력과 계획서가 말하고,
> 무엇을 다음에 할지는 그때 사용자가 정합니다.

## 4. 등록 «면제» — 이 지도가 덮지 않는 것

**리서치 산출물은 등록 대상이 아닙니다.** `tests/test_index.py` 가 `docs/` 아래만 검사합니다.

| 폴더 | 왜 면제인가 |
| --- | --- |
| `dossier/` | **회차마다 늘어납니다.** 등록을 강제하면 에이전트가 회차마다 이 파일을 고쳐야 하고, 안 고치면 품질 검증이 실패하는데 **무인 실행에는 고칠 사람이 없습니다.** 강제 장치가 파이프라인을 멈추는 구조가 됩니다 |
| `runs/` | 같은 이유. 게다가 그 회차의 원자료라 읽히려고 있는 것이 아닙니다 |
| `ledger/` | 후보 목록이지 문서가 아닙니다 |
| `docs/plans/` | 주기적으로 전부 삭제되는 임시 산출물입니다. 폴더는 `.gitkeep` 으로 남깁니다 — 사라지면 계획서 게이트 훅이 **조용히 꺼집니다** |

**이 지도는 「세션이 무엇을 읽어야 하나」의 지도이고, dossier 는 읽히려고 있는 게 아니라
«나가려고» 있습니다.** 둘을 한 목록에 담으면 지도가 산출물 목록에 묻힙니다.
