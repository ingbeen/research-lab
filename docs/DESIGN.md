# 자율 리서치 파이프라인 — 웹 리서치 우선 설계

> 원본 설계서(`자율 퀀트 리서치 파이프라인 구현 가능성 검토 및 방법론 설계서.md`)를
> **「웹 리서치만」 범위로 다시 깎은 것**입니다. 구현·백테스트·매매 보고는 이번 범위에서 뺐습니다.
>
> **이 문서는 verify-lab 의 것이 아닙니다.** 구현은 별도 저장소로 가고, 이 문서는 그 저장소가
> 생기기 전의 설계 논의입니다. 그래서 `docs/` 가 아니라 원본 설계서 옆(저장소 루트)에 둡니다.
>
> **[실측]** 표시는 이 PC 에서 명령을 돌려 확인한 것이고, **[미검증]** 은 아직 확인 못 한 것입니다.
> 둘을 섞지 않습니다 — 「못 찾은 것」과 「아니라고 확인한 것」은 다릅니다.

## 0. 세 줄 요약

1. **만드는 것은 「매매법 발굴기」가 아니라 «검증 의뢰서 생산기»입니다.** 밤사이 돌려서
   나오는 것은 수익률이 아니라 **"이건 재볼 가치가 있다 / 없다"는 근거 문서 한 장**입니다.
   재는 일은 verify-lab 이 이미 합니다.
2. **넓게 훑지 않고 하룻밤에 하나를 끝까지 팝니다.** 후보 30개를 얕게 보는 것보다
   하나를 20페이지로 파는 쪽이 목적에 맞습니다 — 남는 토큰을 쓰는 것이 목적이니까요.
3. **품질은 프롬프트가 아니라 «기계»가 지킵니다.** "반증도 찾아라"라고 시키는 것과
   "반증 칸이 비면 문서가 완성되지 않는다"는 다릅니다. 후자만 실제로 지켜집니다.

## 1. 무엇이 원본 설계서에서 바뀌었나

원본은 6단계(리서치 → 트리아지 → 구현 → 백테스트 → 검증 → 보고)였습니다.
**#3 지시에 따라 앞 두 단계만 남기고, 대신 그 두 단계를 훨씬 깊게 만듭니다.**

| 원본 설계서 | 이번 범위 | 왜 |
| --- | --- | --- |
| 리서치 → 트리아지 → **구현 → 백테스트 → 보고** | 리서치 → 트리아지에서 **멈춤** | #3 |
| 하룻밤에 여러 후보를 얕게 | 하룻밤에 **한 후보를 끝까지** | #4 |
| DSR · Harvey-Liu haircut · CPCV · PBO | **전부 뺌** | 잴 대상이 없는데 통계 게이트를 먼저 지으면 쓰이지 않는 코드가 됩니다. 백테스트 단계가 생기는 날 넣습니다 |
| 임베딩 + FAISS + LLM-judge 중복 판정 캐스케이드 | **사람이 읽는 원장 파일 하나** | 아래 §6 에서 밀어냅니다 |
| 리워드 해킹 방어(채점 격리·홀드아웃 봉인) | **환각 출처 검사로 축소** | 자기 채점할 백테스트가 없으니 해킹할 점수도 없습니다. 남는 위험은 「없는 논문을 지어내는 것」 하나입니다 |
| 4시간 통짜 세션 | **단계마다 짧은 세션 + 파일로 인계** | 원본의 권고와 같고, verify-lab 의 「상태의 진실은 디스크에」와도 같습니다 |

### 밀어내는 것 셋 — 지금 지으면 손해입니다

**#1. 임베딩·FAISS 중복 판정.** 하룻밤에 후보 하나면 **1년에 수십 개**입니다.
수십 줄짜리 목록은 사람이 읽고, 에이전트도 통째로 읽습니다. 벡터DB 는 후보가 수천 개일 때의
도구입니다. **원장은 마크다운 표 한 장으로 시작하고**, 읽기 버거워지는 날 갈아탑니다.

**#2. 통계 게이트(DSR·CPCV).** 이건 **백테스트 결과를 채점하는** 도구입니다.
이번 범위엔 백테스트가 없습니다. 더구나 verify-lab 에 이미 후보 판정 기준(1차 게이트·등급)이
있으므로, 새 저장소가 자기만의 판정 기준을 또 만들면 **같은 질문에 두 가지 답이 나옵니다.**

**#3. 홀드아웃 봉인.** 같은 이유입니다. 다만 **사전등록(pre-registration)은 남깁니다** —
"측정하기 전에 가설과 측정 방법을 먼저 확정해 문서에 박는다"는 이번 범위에서 **가장 값싸고
가장 효과 큰 방어**이고, 산출물이 곧 사전등록서가 됩니다.

## 2. 이 파이프라인이 실제로 뱉는 것

밤에 돌면 아침에 파일 하나가 생깁니다. **이게 전부이고, 이게 제품입니다.**

```
research-lab/                      ← 새 저장소
├── ledger/
│   └── 원장.md                    ← 지금까지 본 후보 전부 (한 줄씩). 중복 방지의 전부
├── dossier/
│   └── 20260913_기관_순매수_추종.md   ← 오늘 밤의 산출물. 아래 11칸짜리
└── runs/
    └── 20260913_0100/             ← 그날의 원자료 (검색어·URL·세션로그·비용)
```

### 산출물(dossier)의 11칸 — 한 칸이라도 비면 «미완성»입니다

#### 🔴 산출물 하나가 «독립»이어야 합니다 — 가장 중요한 제약

**이 dossier 는 verify-lab 을 위한 문서가 아닙니다.** verify-lab 에서 실행될 뿐이고,
**어느 프로젝트에든 · 아직 없는 신규 프로젝트에든 그대로 넘길 수 있는 근거 문서**입니다.

그래서 이 규칙이 다른 모든 것보다 앞섭니다.

> **다른 문서를 한 장도 열지 않고 판단할 수 있어야 한다.**

| 쓰지 않는다 | 대신 쓴다 |
| --- | --- |
| "verify-lab 원칙 12 의 칸당 10건 하한에 걸린다" | "표본이 20건이라 시기를 둘로 쪼개면 칸당 10건이다. **칸당 10건 미만이면 우연과 구별되지 않으므로** 시기 분해를 할 수 없다" |
| "`storage/market/` 에 이미 있다" | "일봉만 필요하다. **국내 ETF 일봉은 pykrx 로 받을 수 있고**, 이 기계에는 이미 받아둔 것이 있다" |
| "기존 측정 계층을 쓰면 된다" | 측정 설계를 **그 자리에 전부 적는다** |
| "판정 기준은 그 저장소 규약을 따른다" | **적용한 기준 자체를 dossier 안에 적는다** |

**🔴 「중복되니 빼자」는 판단을 하지 않습니다.** 가리키는 문서가 그 프로젝트에 없으면
**dossier 는 그 순간 쓸모없는 종이가 됩니다.** 링크가 깨지는 게 아니라 **판단이 불가능해집니다.**

> **이건 전역 규칙 「코드에서 파생 가능한 정보를 복제하지 않는다」의 «의도적 예외»입니다.**
> 그 규칙은 **한 저장소 안에 머무는 문서**를 전제합니다. dossier 는 **저장소 밖으로 나가는
> 문서**라 전제가 다릅니다 — 옮겨간 자리에서 포인터는 전부 죽습니다.
> 복제 대신 링크를 쓰는 문서는 이 파이프라인 «안»의 것들(원장·로그·설계서)이고,
> **dossier 만 예외입니다.**

---

**순서는 「결론 먼저, 근거 뒤」입니다.**
아침에 읽는 사람이 **위 다섯 칸만 보고 판단**할 수 있어야 하고, 아래 여섯 칸은
그 판단을 의심할 때 내려가는 자리입니다.

| # | 칸 | 무엇을 적나 | 비면? |
| --- | --- | --- | --- |
| 1 | **한 줄 주장** | "무엇을 언제 사고 언제 파는가" 한 문장 | 기계 차단 |
| 2 | **판정** | 잴 가치 있음 / 보류 / 기각 **+ 반드시 이유** | 기계 차단 |
| 3 | **왜 우위가 있을 수 있나** | 리스크 프리미엄 · 행동 편향 · 제도/미시구조 | 기계 차단 |
| 4 | **데이터 실현가능성** | 필요한 데이터 · 있나 · 어떻게 받나 · 막히면 무엇으로 | 기계 차단 |
| 5 | **집행 현실성** | 살 수 있나 · 신호 빈도 · 배수 가능한가 | 기계 차단 |
| 6 | **출처 계보** | 누가 처음 말했고 누가 베꼈나. **복제를 뺀 진짜 소스 수** | 기계 차단 |
| 7 | **찬성 근거** | 출처 URL · 발행일 · 1차/2차 구분 | 기계 차단 |
| 8 | **반증** | 반대 주장과 그 출처 | **기계 차단 (핵심)** |
| 9 | **왜 사라졌을 수 있나** | 발표 후 소멸 · 제도 변화 · 시장 구조 변화 | 기계 차단 |
| 10 | **측정 설계 초안** | verify-lab 이 그대로 잴 수 있는 형태 (§5) | 기계 차단 |
| 11 | **미검증 목록** | 확인 못 한 것 | **비는 게 오히려 의심스러움** |

> **판정(2번)이 위에 있다고 판정을 «먼저» 쓰는 것은 아닙니다.** 채우는 순서는 여전히
> 6→7→8→9→4→5→3 이고, 2번은 **마지막에** 씁니다. 문서의 순서와 작업의 순서는 다릅니다.

#### 🔴 5번 칸에 비용·세금·슬리피지를 넣지 않습니다

**케이스마다 다르고 단정할 수 없기 때문입니다.** 증권사·계좌·이벤트에 따라 자릿수가
달라지고, 그 폭이 회당 기대값과 같은 크기라 **어떤 값을 넣느냐가 결론을 만듭니다.**
루트 `CLAUDE.md` 가 verify-lab 에 같은 규정을 이미 두고 있습니다 —
「사용자가 별도로 요청할 때만」.

| 5번 칸에서 묻는 것 | 묻지 않는 것 |
| --- | --- |
| 살 수 있는 상품이 있나 | ~~수수료를 빼면 남나~~ |
| 신호가 얼마나 자주 오나 | ~~슬리피지 반영 후 성적~~ |
| 배수를 걸 수 있나 | ~~세금~~ |
| 분·초 단위 집행이 필요한가 | |

> **왜 "기계 차단"이라고 쓰나**: 프롬프트로 "반증도 써라"라고 시키면 **형식적으로 한 줄 쓰고
> 넘어갑니다.** 원본 설계서가 인용한 실험도 같은 말을 합니다 — 프롬프트 개입의 효과는
> 벤치마크마다 들쭉날쭉했고, 환경을 하드닝한 쪽만 일관되게 먹혔습니다.
> 그래서 **러너(파이썬)가 산출물을 읽어 칸이 비었으면 그 밤을 "미완성"으로 기록**합니다.
> 에이전트가 자기 점수를 매기지 않습니다.

### 채워 본 예시 — 「1월 효과」라면 이렇게 나옵니다

11칸이 추상적으로 들리므로 **실제로 채우면 어떤 문서가 나오는지** 보입니다.
(아래는 설명용 예시입니다. 실제 수치가 아니라 «모양»을 보이는 것입니다.)

**`#` 는 «문서에서의 칸 번호»이고, 행은 문서 순서가 아니라 근거를 쌓아가는 순서로 놓았습니다.**
그래서 번호가 건너뜁니다 — 그게 정상입니다. **정본 채우는 순서는 바로 위 단서**에 있습니다.

| # | 칸 | 이 후보에서는 |
| --- | --- | --- |
| 1 | 한 줄 주장 | "소형주는 1월에 더 오른다. 12월 말에 사서 1월 말에 판다" |
| 6 | 출처 계보 | 원본은 1976년 논문 한 편. 검색에 **14곳**이 걸렸지만 11곳이 그 한 편을 받아쓴 복제 → **독립 소스는 3곳** |
| 7 | 찬성 근거 | 원논문 · 재검증 논문 · 국내 대상 후속연구 (각각 URL·발행일·1차/2차) |
| 8 | 반증 | "발표 후 소멸했다"는 반박 · "거래비용 넣으면 사라진다" · "최근 20년 재현 실패" (각각 URL) |
| 3 | 왜 우위가 있을 수 있나 | 연말 절세 매도 후 되사기 · 기관 윈도드레싱 · 1월 신규 자금 유입 |
| 9 | 왜 사라졌을 수 있나 | 1976년 발표로 널리 알려짐 · **한국은 절세 매도 유인이 다름**(양도세 구조가 미국과 다름) |
| 10 | 측정 설계 초안 | 대상 **KODEX 코스닥150**(지수 아님) / 진입 12월 20~31일 각 거래일 / 청산 1월 말일 기준 격자 / 기준선 같은 보유기간 전체 평균 / **방향 미정** / 미래 참조 없음(달력만 보면 정해짐) / **예상 표본 연 1회 × 20년 = 20건** |
| 4 | 데이터 실현가능성 | 일봉만 필요 · **국내 ETF 일봉은 pykrx 로 받을 수 있다** · 이 기계에 코스닥150 계열을 이미 받아둔 것이 있다 |
| 5 | 집행 현실성 | ETF 있음 O · **신호가 연 1회 (문제)** · 국내는 2배까지 가능 · 보유 1개월이라 회당 크기는 충분 |
| 2 | **판정** | **보류** — 경제적 근거는 있으나 **표본이 20건(연 1회 × 20년)** 이라 시기를 둘로 쪼개면 **칸당 10건**이다. **칸당 10건 미만이면 우연과 구별되지 않으므로** 「어느 시기가 만든 값인가」를 물을 수 없다. 잴 수는 있으나 그 질문이 막힌다 |
| 11 | 미검증 | 국내 절세 매도 유인의 실제 크기 · 2000년 이전 코스닥 데이터 품질 |

**여기서 봐야 할 것 셋**

- **5번 칸이 문제를 잡았습니다** — "연 1회"는 읽자마자 걸리는데, 근거만 모으는 문서였다면
  안 나왔을 항목입니다. 칸이 정해져 있으니 **안 물을 수가 없습니다.**
- **2번이 「보류」인 것도 성공입니다.** 이 파이프라인의 가치는 찾는 것보다
  **가짜를 아침 전에 걸러내는 것**입니다. 매일 "발견!"이 나오면 그게 고장입니다.
- 🔴 **판정 이유가 「원칙 번호」가 아니라 «기준 자체»를 답니다** — 「원칙 12 에 걸린다」가 아니라
  「칸당 10건 미만이면 우연과 구별되지 않는다」입니다. 그래야 **다른 저장소를 한 장도 열지 않고**
  「왜 보류지?」에 답이 됩니다. 이 dossier 는 저장소 밖으로 나가므로 번호는 그 자리에서 죽습니다.
  4번 칸의 「pykrx 로 받을 수 있다」도 같은 이유입니다 — 「`storage/market/` 에 있다」로 적으면
  그 폴더가 없는 프로젝트에서는 **무엇을 어떻게 받아야 하는지가 통째로 사라집니다**

```
                   │  · 어디까지 했나를 «파일»로 안다                │
                   │  · 단계마다 claude 를 «짧게» 부른다             │
                   │  · 예산·타임아웃·재시도를 건다                  │
                   └───────────────────┬──────────────────────────┘
                                       │
        ┌──────────────┬───────────────┼───────────────┬──────────────┐
        ▼              ▼               ▼               ▼              ▼
   ┌─────────┐   ┌──────────┐   ┌───────────┐   ┌──────────┐   ┌─────────┐
   │ 1.수집   │   │ 2.반증    │   │ 3.계보    │   │ 4.실현성  │   │ 5.작성  │
   │ 찬성근거 │   │ «별도     │   │ 누가 원본 │   │ 데이터·  │   │ 11칸    │
   │          │   │  세션»    │   │ 인가      │   │ 집행     │   │ 채우기  │
   └─────────┘   └──────────┘   └───────────┘   └──────────┘   └─────────┘
        └──────────────┴───────────────┴───────────────┴──────────────┘
                                       │  각 단계의 산출물은 파일
                                       ▼
                   ┌──────────────────────────────────────────────┐
                   │  게이트 (파이썬) — 11칸 검사 + URL 실재 검사    │
                   │  통과 → dossier 확정 · 원장에 한 줄 추가        │
                   │  실패 → 「미완성」으로 남기고 다음 밤 재시도      │
                   └──────────────────────────────────────────────┘
```

**핵심은 상자 사이의 «선»입니다.** 선 위를 오가는 것이 대화가 아니라 **파일**이라서,
중간에 멈춰도 거기서 이어집니다. 이게 §8(한도 소진) 대응의 절반입니다.

### 3.1 밤의 «첫 단계»는 새 후보가 아니라 «어제의 미완성»입니다

위 그림에서 빠져 있던 것이고, **순서가 반대면 사고가 납니다.**

**그리고 밤은 «한 장 만들고 끝»이 아니라 예산이 남는 한 «돕니다».**

```
  밤 시작 — 예산·디스크 여유 확인
    │
    ├──────────────────────────────────────────────────────┐
    │                                                       │
    ▼                                                       │
  ① 미완성이 있나? ──── 있다 ──→ «이어서» 판다              │
    │                             ↳ 어느 단계에서 멈췄는지는 │
    │ 없다                          파일이 안다              │
    ▼                                                       │
  ② 원장에 안 판 후보가 있나? ── 있다 ──→ 심층 (dossier 1장)│
    │                                                       │
    │ 없다                                                  │
    ▼                                                       │
  ③ 탐색 — 후보 목록을 채운다 (싸다)                        │
    │                                                       │
    ▼                                                       │
  ④ 남은 예산이 «한 단위» 더 되나? ── 된다 ────────────────┘
    │
    │ 안 된다 (또는 탐색조차 못 할 만큼 적다)
    ▼
  밤 종료 — 쓴 예산·남은 예산을 로그에 적는다
```

**왜 ①이 첫 단계여야 하나** — 미완성을 두고 새 후보를 꺼내면 **미완성이 계속 쌓입니다.**
한 번 막힌 후보는 다음 밤에도 같은 이유로 막힐 가능성이 높은데, 새것을 계속 꺼내면
**아무도 그 사실을 모른 채 미완성만 늘어납니다.**

그래서 **같은 미완성이 N번 연속 실패하면 「막힘」으로 원장에 사유와 함께 박고 넘어갑니다.**
무한히 붙들고 있는 것과 조용히 버리는 것 사이의 답입니다.

**①이 먼저라서 미완성은 구조적으로 최대 «1개»입니다.** 새것을 시작하기 전에 반드시
미완성을 처리하므로, 한 밤이 끝에서 하나를 못 끝내도 다음 밤이 그것부터 잡습니다.

### 3.1.1 「한 장 만들고 토큰이 남으면 중지」가 아닙니다

**남는 토큰을 쓰는 것이 이 프로젝트의 목적**이라, 일찍 끝났다고 멈추면 목적과 어긋납니다.

| 상황 | 어떻게 |
| --- | --- |
| dossier 한 장을 끝냈는데 예산이 넉넉하다 | **다음 후보로 간다** (④ → ①로 돌아감) |
| 미완성을 이어받아 **조금 쓰고 완성**했다 | 같다. **거의 다 남은 예산으로 새 후보를 시작한다** |
| 예산이 한 장을 새로 파기엔 모자라다 | **탐색**으로 전환 — 후보 목록만 채운다. 훨씬 싸다 |
| 탐색조차 못 할 만큼 적다 | 종료. **남은 예산을 로그에 적는다** (다음 밤 계획에 쓴다) |

**「한 단위」가 얼마인지는 실측으로 압니다** — 지난 밤들의 로그에서 dossier 한 장의
평균 비용을 그때그때 계산합니다. **누적 파일로 저장하지 않습니다**(§5.5 B) —
매번 로그를 훑어 계산하면 하루 걸러도 표본이 하나 없을 뿐입니다.

> **모자란 예산으로 시작해 미완성이 되는 것은 «사고가 아닙니다».**
> 다음 밤이 ①에서 이어받으므로 일이 버려지지 않고, 최대 1개라 쌓이지도 않습니다.
> 다만 **평균의 절반도 안 남았으면 시작하지 않습니다** — 시작 비용(검색·컨텍스트 적재)이
> 매번 다시 들어 순 낭비가 됩니다.

### 3.1.2 깊이는 줄이지 않습니다

「예산이 남으니 한 장을 더」는 **장수**를 늘리는 것이지 **깊이**를 나누는 것이 아닙니다.
한 장은 언제나 11칸을 다 채우고 게이트를 통과해야 하며, **예산이 모자라면 장수를 줄이지
칸을 줄이지 않습니다.** 칸을 줄이면 그건 미완성이지 짧은 dossier 가 아닙니다.

### 3.2 모든 단계가 «왜 그렇게 판단했는지»를 로그로 남깁니다

산출물(dossier)은 **결론**이고, 로그는 **과정**입니다. 둘을 섞으면 dossier 가 읽히지 않습니다.

`runs/20260913_0100/` 안에 단계마다 한 파일씩 쌓습니다.

| 로그에 적는 것 | 없으면 나중에 못 하는 일 |
| --- | --- |
| **무엇을 읽었나** — 검색어 전부 · 연 URL 전부 · 읽은 저장소 문서 경로 | "이 결론이 어디서 왔지"를 되짚을 수 없다 |
| **무엇을 기준으로 판단했나** — 어느 규칙·어느 원칙 번호를 적용했나 | 기준을 고쳤을 때 **어느 과거 판정이 영향받는지** 모른다 |
| **무엇을 버렸고 왜** | 다음에 같은 후보를 또 파면서 같은 것을 또 버린다 |
| **분류 못 한 실패의 원문** (§4) | 처음 한도에 부딪히는 날 그 답을 못 얻는다 |
| 그 단계의 토큰·비용·소요 시간 | 밤 예산을 정할 근거가 없다 |

**이게 「업데이트하기 좋게」의 실체입니다.** 게이트 기준을 바꾸거나 프롬프트를 고쳤을 때,
**과거 밤의 로그를 다시 읽어 「지금 기준이면 판정이 달라졌을 후보」를 찾아낼 수 있습니다.**
로그가 없으면 바꾼 뒤의 것만 알 수 있고, 그 전은 통째로 깜깜합니다.

> **로그는 「사람이 읽을 것」이 아니라 「나중에 기계가 훑을 것」으로 씁니다** —
> 줄글이 아니라 구조화(JSONL)로 남겨야 위 질문에 답할 수 있습니다.
> 다만 **누적 집계는 만들지 않습니다**(§5.5 B) — 로그는 그날 것만 쌓고, 집계가 필요하면
> 그때 전체를 훑습니다. 집계를 미리 누적하면 하루 걸렸을 때 **조용히 틀어집니다.**

## 4. 두 종류의 밤

#4 의 "많이 말고 깊게"를 구조로 만든 것입니다. **밤마다 같은 일을 하지 않습니다.**

| | **탐색 밤** | **심층 밤** |
| --- | --- | --- |
| 빈도 | 가끔 (후보 재고가 떨어지면) | **대부분의 밤** |
| 하는 일 | 넓게 훑어 후보 **목록**만 만든다 | 후보 **하나**를 끝까지 판다 |
| 산출물 | 원장에 후보 10~20줄 추가 (한 줄 주장만) | dossier 11칸 한 장 |
| 깊이 | 얕아도 된다 | 여기가 진짜 |
| 토큰 | 적게 | **많이 — 여기 쏟는다** |

> **왜 나누나**: 한 밤에 「훑고 + 파기」를 같이 하면 둘 다 어중간해집니다.
> 그리고 컨텍스트가 터집니다 — 후보 20개의 검색 결과를 다 들고 한 개를 깊게 파는 것은
> 한 세션에 안 들어갑니다. **탐색이 재고를 쌓고, 심층이 하나씩 꺼내 씁니다.**

**심층 밤의 대상은 어떻게 고르나** — 원장에서 고릅니다. 고르는 규칙은 단순하게 시작합니다:
**"아직 안 판 것 중 위에서부터"**. 원본 설계서의 밴딧·커버리지 맵은 후보가 쌓인 뒤에
필요해지면 그때 넣습니다.

## 5. 지식은 «들여오고», 산출물은 «자립»시킵니다

두 방향을 헷갈리면 안 됩니다. **들어오는 것은 링크를 써도 되고, 나가는 것은 안 됩니다.**

| 방향 | 무엇 | 링크 써도 되나 |
| --- | --- | --- |
| **들어옴** — 리서치가 «참고»하는 지식 | 어떤 데이터를 어떻게 받을 수 있나, 어떤 함정이 있나 | **된다.** 파이프라인 안에 머무는 문서다 |
| **나감** — dossier | 후보 하나의 근거와 판정 | **안 된다.** 저장소 밖으로 나가므로 포인터가 전부 죽는다 (§2) |

### 5.1 들여올 것 — 데이터 카탈로그

10번 칸(측정 설계 초안)과 4번 칸(데이터 실현가능성)을 채우려면
**"이 데이터를 실제로 받을 수 있나"** 를 알아야 합니다. 이건 새로 알아내면 낭비이고,
더 나쁘게는 **틀리게 알아냅니다.** 이미 실측으로 밝혀진 것이 세 저장소에 흩어져 있습니다.

| 카탈로그에 담을 것 | 원본이 어디 있나 |
| --- | --- |
| 국내 시세를 어떻게 받나, 수정주가 함정 | verify-lab `reference/pykrx_실측기록.md` |
| ETN 시세 받는 법 | verify-lab `docs/spec/레버리지_ETF_괴리_설계.md` |
| 국내 선물 계약별 시세, 거를 것 | verify-lab `docs/spec/선물_대_레버리지_ETF_설계.md` |
| 만기 달력·배당락·분배락이 결과를 오염시키는 방식 | verify-lab `docs/spec/옵션_만기일_설계.md` |

**카탈로그는 research-lab 안에 살고, 「무엇을 받을 수 있나」만 요약합니다.**
자세한 방법은 원본을 가리킵니다 — 이건 파이프라인 «안»의 문서라 링크가 살아 있습니다.

### 5.2 나갈 것 — dossier 는 자기 발로 서야 합니다

**10번 칸에 측정 설계를 «전부» 적습니다.** 「그 프로젝트 규약대로」라고 쓰지 않습니다.

| 10번 칸에 반드시 적는 것 | 왜 — dossier 안에 이 이유까지 적는다 |
| --- | --- |
| 신호 정의에 **미래 참조가 없음**을 명시 | 판정 시점에 알 수 없는 정보로 신호를 정의하면 **못 잴 것을 재게 된다** |
| 대상은 **실제로 살 수 있는 상품**(ETF 등). 없으면 그 사실과 이유 | 지수로 잰 성적은 **집행할 수 없는 성적**이다 |
| **진입 시점 격자 × 보유 기간 격자** — 한 값이 아니라 여러 값 | 한 값만 재면 그게 **가장 좋은 값이라서 고른 것인지** 구별되지 않는다 |
| **기준선**이 무엇인지 | 주식은 장기 상승해서 아무 날에나 사도 오른 비율이 절반을 넘는다. **기준선 없는 비율은 사람을 속인다** |
| **방향을 미리 정하지 않음** (위·아래 둘 다) | 「내린다」도 유효한 신호다. 방향을 먼저 정하면 반대쪽 발견을 통째로 놓친다 |
| **예상 표본 수** | 표본이 적으면 소수점 차이로 우열을 가릴 수 없다 |

> **부수 효과 — 이게 사전등록입니다.** 재기 전에 측정 방법이 문서에 박히므로,
> **결과를 보고 나서 기준을 고치는 일**이 구조적으로 막힙니다.
> 원본 설계서가 별도 장치로 만들려던 것을 공짜로 얻습니다.

**그래서 dossier 는 길어집니다. 의도한 것입니다** — 짧게 만들려고 「아는 사람은 아는」
포인터로 줄이는 순간, **모르는 사람에게는 판단 불가능한 문서**가 됩니다.

## 5.5 세 저장소와 전역 하네스에서 «이미 풀린» 것들

`quant` · `quant-notify` · `verify-lab` 과 전역 `~/.claude` 를 훑었습니다.
**새 저장소가 처음부터 만들 필요가 없는 것들이 나왔고, 하나는 설계를 고치게 했습니다.**

### 🔴 A. `report_lint.py` 가 11칸 게이트의 «원형»입니다

전역 훅 `~/.claude/hooks/report_lint.py` 는 이미 같은 문제를 풀었습니다 —
**조사리포트에 「확인하지 못한 것」 절이 없으면 `block`** 합니다.
그 훅의 docstring 에 실측까지 있습니다.

> "도입 시점(2026-09-10) 전수 조사에서 그 절을 가진 리포트는 «절반에 한참 못 미쳤다»."

**제 4번·8번·11번 칸 강제가 검증된 패턴이라는 뜻이고, 설계 결정 셋이 그대로 넘어옵니다.**

| 그 훅의 결정 | 새 저장소의 게이트에 그대로 |
| --- | --- |
| **절의 「존재」만 본다. 내용은 검사하지 않는다** | "무엇을 못 봤는지는 조사한 사람만 알고, **빈 경우에도 「없음」이라 적을 길이 남아야** 한다". 게이트가 반증의 «질»을 판정하려 들면 그 자체가 또 하나의 판단자가 된다 |
| **저장은 이미 끝난 뒤다 — 되돌리지 않고 «다음 턴에 채우게» 만든다** | 미완성 표시 → 다음 밤 재시도와 정확히 같은 구조 |
| **Bash 경유 수정은 검사하지 않는다** | 읽기와 쓰기가 구분되지 않아, 무관한 명령이 기존 위반 때문에 막히는 것을 피한다 |

### 🔴 B. quant-notify 의 「무상태」 축 — 제 설계와 정면으로 부딪힙니다

`quant-notify/CLAUDE.md` 가 **만들지 않겠다고 못박은 것**에 제가 쓰려던 게 둘 들어 있습니다.

> "자동 재시도 · **부분 성공** · 값 보간 · 발송 이력 저장 · …"
> "매일 갱신되는 누적 상태를 만들지 않습니다. **그것이 이 저장소가 존재하는 이유입니다.**"

그리고 판정 기준이 표로 있습니다.

| | 자동 누적 상태 | 사람이 쓰는 파일 |
| --- | --- | --- |
| 갱신 주체 | 매 실행마다 프로그램이 | 사람이, 바뀔 때만 |

## 6. #6 — 노이즈와 반증을 어떻게 다루나

**이미 답이 있습니다.** 전역 스킬 `~/.claude/skills/web-research/SKILL.md` 가
정확히 이 규율을 담고 있고, 이미 쓰고 있습니다. **새로 만들지 않고 그것을 부릅니다.**

그 스킬이 강제하는 것 넷 — 이게 그대로 이 파이프라인의 뼈대가 됩니다.

| 규율 | 파이프라인에서의 구현 |
| --- | --- |
| **검색어를 갈아 끼운다** (한/영, 업계어/일상어, 3회 이상) | 1단계가 검색어 목록을 **파일로 남긴다.** 3개 미만이면 게이트 실패 |
| **반증을 따로 검색한다** (`X 비판` · `X debunked` · `X doesn't work`) | **2단계를 별도 세션으로 분리.** 찬성 근거를 모은 세션이 반증도 찾게 하지 않는다 |
| **소스의 독립을 잰다** (같은 숫자·같은 예시 반복 = 복제, 소스 수는 1) | 3단계가 **계보표**를 만든다. 6번 칸 |
| **1차 출처까지 내려간다** | 2차 서술만 있으면 그 사실은 **「미검증」** 으로 적는다 |

### 왜 반증을 «별도 세션»으로 떼나

같은 세션에서 찬성 근거를 20개 모은 다음 "이제 반증을 찾아라"라고 하면,
**이미 쌓인 맥락이 반증 탐색을 방해합니다.** 자기가 방금 지지한 것을 스스로 무너뜨리라는
요구이고, 이건 사람도 잘 못 합니다.

**2단계 세션은 후보의 한 줄 주장만 받습니다.** 1단계가 뭘 찾았는지 모릅니다.
"이 주장을 깨라"가 그 세션의 유일한 임무이고, **많이 찾을수록 잘한 것**입니다.

### 🔴 이번 범위에서 유일하게 남는 「위조」 위험 — 없는 출처

백테스트가 없으니 점수를 부풀릴 대상이 없습니다. 대신 **존재하지 않는 논문·URL 을
그럴듯하게 지어내는 것**이 남습니다. 그리고 이건 **읽어서는 구별되지 않습니다.**

**기계로 막습니다** — 게이트가 dossier 안의 모든 URL 을 실제로 호출해
살아 있는지 확인하고, 죽은 URL 이 하나라도 있으면 그 밤을 미완성으로 만듭니다.
사람이 판단할 일이 아닙니다.

## 8. #5 — 정해야 할 것들 (실측 근거 포함)

### 8.1 어디서 돌리나 — WSL 지금 / mac 나중 / Docker?

**[실측] 이 PC 에서 확인한 것**

| 항목 | 값 |
| --- | --- |
| Docker | 29.2.1, 서버 OS `Ubuntu 24.04.3 LTS` → **WSL 안의 네이티브 엔진**(Docker Desktop 아님) |
| systemd | **켜져 있음** (`/etc/wsl.conf` 에 `systemd=true`) |
| cron | `/usr/sbin/cron` 있음 |
| Python / Poetry | 3.12.3 / 1.8.2 |
| Claude Code | **2.1.70** |

**추천: Docker 를 씁니다.** 이유가 둘인데 **둘의 무게가 다릅니다.**

1. **(큰 이유) 이전 비용을 0 에 가깝게 만든다.** WSL 은 amd64, mac mini 는 arm64 입니다.
   컨테이너로 싸두면 옮길 때 바뀌는 것이 **트리거 한 줄**뿐입니다. 컨테이너 없이 짜면
   경로·셸·스케줄러가 전부 달라 옮기는 날 다시 짭니다.
2. **(작은 이유) bypass 모드의 사정거리를 좁힌다.** 무인 실행에서 승인창이 뜨면 프로세스가
   그냥 멈춥니다(#5-2 의 걱정이 맞습니다). 그래서 bypass 를 켜야 하는데,
   **켜는 순간 에이전트가 이 PC 의 아무 파일이나 만질 수 있습니다** — 다른 저장소, `~/.claude`,
   SSH 키까지. 컨테이너 안이면 **bind mount 한 폴더로 한정**됩니다.

> **🔴 정직하게: 컨테이너는 여기서 «보안 샌드박스가 아닙니다».**
> 리서치 파이프라인은 **인터넷이 반드시 필요**합니다. Anthropic 이 bypass 를 권하는 조건은
> "인터넷 없는 샌드박스"인데, 우리는 그 조건을 못 맞춥니다.
> 컨테이너가 막아주는 것은 **파일 시스템**이지 네트워크가 아닙니다.
> 그래서 컨테이너 안에는 **Claude 토큰 말고 다른 자격증명을 넣지 않습니다** —
> `.env` · KRX 계정 · 구글 시트 키는 **안 들어갑니다.** 리서치엔 필요 없습니다.

**대안도 적어 둡니다** — Docker 없이 `--allowedTools` 로 도구를 좁히고
`--permission-mode acceptEdits` 로 가는 길이 있습니다. 더 단순하지만 **이전 비용을 나중에
한꺼번에 냅니다.** 지금 이전을 전제하고 시작하는 상황이라 Docker 쪽을 권합니다.

#### 컨테이너를 써도 «보고서는 내 폴더에 그대로» 생깁니다

| 걱정 | 실제 | 어떻게 |
| --- | --- | --- |
| 보고서가 컨테이너 안에 갇히나 | **안 갇힙니다** | 저장소 폴더를 **bind mount** 합니다. 컨테이너가 쓰는 파일이 곧 WSL 의 그 파일이라, **VSCode 소스 컨트롤에 diff 로 바로 뜹니다** |
| 컨테이너가 죽으면 산출물도 사라지나 | **안 사라집니다** | 같은 이유입니다. 컨테이너 안에는 **상태를 두지 않습니다** |
| **파일 소유권이 꼬이나** | **꼬입니다 — 안 막으면** | **[실측]** 내 계정은 `uid=1000`. 컨테이너를 기본(root)으로 돌리면 **root 소유 파일**이 생겨 WSL·VSCode 에서 못 고칩니다. `--user 1000:1000` 로 고정합니다 |
| 아티팩트로 나오나 | **안 씁니다** | 전역 규칙대로 **산출물은 파일**입니다. 아티팩트는 VSCode diff 흐름 밖이라 검토가 끊기고, 무인 실행에서는 더더욱 볼 사람이 없습니다. 컨테이너에 **아티팩트 도구를 아예 주지 않습니다**(`--tools` 로 필요한 것만) |

#### 🔴 전역 `~/.claude` 를 마운트할 것인가 — 이게 진짜 갈림길입니다

**[실측]** §6 이 의존하는 `web-research` 스킬은 **전역**(`~/.claude/skills/`)에 있습니다.
컨테이너가 그걸 못 보면 **소스 독립성·반증·1차 출처 규율이 통째로 사라지는데, 에러는 안 납니다.**
문서는 여전히 그럴듯하게 나옵니다.

| 길 | 문제 |
| --- | --- |
| `~/.claude` 를 통째로 마운트 | 이모지 차단·DB 차단·하네스 메모리 차단 훅이 따라오고, mac 으로 옮기면 그쪽 `~/.claude` 를 따라 **동작이 달라집니다.** 재현이 안 됩니다 |
| **새 저장소가 자기 리서치 스킬을 소유 (추천)** | 스킬이 git 에 들어가 **버전이 고정**되고 컨테이너가 자립합니다. `web-research` 의 복제가 아니라 **게이트와 짝이 맞는 것**이어야 합니다 — 러너가 "검색어 3개 이상"을 검사하면 스킬도 검색어를 파일로 남기게 시켜야 하고, 둘이 어긋나면 게이트가 조용히 헛돕니다 |

#### 개발은 WSL·mac 을 오가고, 싱크는 git 이 맡습니다

**최종 운용은 mac 한 대지만 초기·구현 단계는 두 PC 를 왔다갔다** 하므로,
설계에 미치는 영향이 넷 있습니다.

| 항목 | 규칙 | 왜 |
| --- | --- | --- |
| **베이스 이미지** | **멀티아치인 것만** (`python:3.12-slim` 은 amd64·arm64 둘 다 있다) | WSL 은 amd64, mac mini 는 arm64. 아치 고정 이미지를 쓰면 한쪽에서 안 뜬다 |
| **경로** | 컨테이너 «안» 경로는 고정(`/work`), **호스트 경로는 바깥에서 주입** | 호스트 경로를 코드에 박으면 `/home/yblee/...` 와 `/Users/...` 가 갈린다 |
| **git 제외** | `.venv/` · `__pycache__/` · 이미지 · 컨테이너 내부 상태 | 아치가 다르면 깨진다. verify-lab 이 이미 같은 `.gitignore` 를 쓴다 |
| **git 포함** | `Dockerfile` · lock 파일 · **리서치 스킬** · 원장 | 이미지 자체는 git 에 안 올라가므로 **Dockerfile + lock 이 재현의 전부**다 |

**`runs/` 를 git 에 올릴지가 남은 판단입니다.** verify-lab 이 같은 문제를 겪었고
`storage/results/` 는 올리되 `meta.json` 만 뺐습니다 — 실행마다 재작성돼 **두 PC 가
pull 할 때마다 충돌**하기 때문입니다. 같은 기준을 적용하면 **dossier·원장은 올리고,
그날의 세션 로그 원문은 빼는** 쪽입니다. 다만 §3.2 의 「나중에 기계가 훑을 로그」가
안 넘어가면 mac 에서 과거를 못 훑으므로, **Phase 1 에서 로그 크기를 재고 정합니다.**

> **[실측 교훈] 다른 저장소에서 poetry 를 부를 때는 `env -u VIRTUAL_ENV` 를 붙입니다.**
> 세션을 시작한 저장소의 가상환경이 셸에 남아 있어, 안 붙이면 **엉뚱한 venv 를 써서
> `ModuleNotFoundError` 가 나고 「패키지가 없다」로 오진합니다.**

### 8.2 시간 — 내가 정할 수 있나

**됩니다. 다만 트리거는 «컨테이너 밖·WSL 밖»에 둡니다.**

🔴 **WSL2 는 Windows 가 잠들면 같이 멈춥니다.** WSL 안의 cron 에 걸면
**PC 가 깨어 있는 동안만** 돕니다. 이건 원본 설계서가 mac 에서 `pmset` 으로 풀려던 것과
같은 문제이고, Windows 에서는 **작업 스케줄러의 "이 작업을 실행하기 위해 절전 모드 해제"**
옵션이 그 역할을 합니다. [미검증] — 이 PC 에서 실제로 깨우는지는 Phase 0 에서 잽니다.

| 지금 (WSL) | 나중 (mac mini) |
| --- | --- |
| Windows 작업 스케줄러 → `wsl.exe -- docker run ...` | `launchd` + `pmset repeat wakeorpoweron` |
| 「절전 해제」 체크 | `caffeinate -i` 로 실행 중 재수면 방지 |

**새벽일 필요 없습니다.** 시각은 지정하면 그대로 씁니다.
다만 **5시간 한도가 「첫 프롬프트부터」 도는 것**이라, 내가 낮에 쓰는 시간대와
겹치지 않는 쪽이 유리합니다. 그 판단은 §8.4 를 보고 같이 정합시다.

### 8.3 한도로 멈추면 — 다시 붙나

**[실측] 현재 CLI 에 있는 것 / 없는 것**

| 있나 | 플래그 | 이 설계에서의 쓸모 |
| --- | --- | --- |
| **있음** | `--session-id <uuid>` | **가장 중요.** 세션 ID 를 «내가 미리 정해서» 넘깁니다. 출력에서 ID 를 긁어낼 필요가 없습니다 |
| **있음** | `-r, --resume <id>` / `-c, --continue` | 그 ID 로 되붙습니다 |
| **있음** | `--fork-session` | 되붙되 새 ID 로 — 원본을 안 건드리고 재시도할 때 |
| **있음** | `--max-budget-usd <금액>` | 단계마다 **하드 상한**. `--print` 에서만 동작 |
| **있음** | `--permission-mode bypassPermissions` | 승인창 원천 차단 |
| **있음** | `--output-format json` | 러너가 결과를 파싱 |
| **있음** | `--json-schema <스키마>` | **산출물 모양을 강제**. 11칸 구조에 그대로 씁니다 |
| **없음** | ~~`--max-turns`~~ | **원본 설계서가 틀렸습니다** — CLI 플래그가 아니라 Agent SDK 옵션입니다. 대신 `--max-budget-usd` 가 같은 일을 더 정확히 합니다 |

**그래서 답은: 되붙을 수 있습니다. 그런데 «되붙는 데 의존하지 않게» 짭니다.**

```
나쁜 설계:  한 세션을 4시간 돌린다 → 중간에 끊김 → resume 에 목숨을 건다
좋은 설계:  단계마다 짧게 부른다 → 끊기면 «그 단계만» 다시 → 앞 단계 산출물은 파일에 그대로
```

resume 은 **보험**이지 뼈대가 아닙니다. 뼈대는 **파일로 인계하는 것**입니다.
그러면 한도로 끊겨도, 컨테이너가 죽어도, PC 가 재부팅돼도 같은 방식으로 복구됩니다.

**[미검증] 두 가지는 Phase 0 에서 반드시 잽니다.**
① 한도가 바닥났을 때 `--output-format json` 이 정확히 어떤 모양으로 실패하는지
(그래야 러너가 「한도 소진」과 「진짜 에러」를 구별합니다).
② 한도 리셋 뒤 `--resume` 이 실제로 이어지는지.
**추측으로 넘어가면 러너가 한도 소진을 버그로 오인해 무한 재시도합니다.**

### 8.4 5시간 한도를 보면서 갈 수 있나 — **절반만 됩니다**

정직하게 나눕니다.

| | 되나 | 근거 |
| --- | --- | --- |
| **내가 쓴 양을 정확히 아는 것** | **됩니다** | **[실측]** 세션 로그(`~/.claude/projects/.../<id>.jsonl`)의 각 줄에 `usage`(input/output/cache 토큰)와 `timestamp` 가 있습니다. 5시간 창으로 잘라 더하면 **내 소비량**이 나옵니다 |
| **이번 실행이 쓴 비용** | **됩니다** | `-p --output-format json` 이 실행별 비용·턴 수를 돌려줍니다 |
| **예산을 못 넘게 막는 것** | **됩니다** | `--max-budget-usd` 하드 상한 |
| **「플랜 한도의 몇 % 남았나」** | **안 됩니다** | **[실측]** CLI 에 usage/quota 플래그가 **없습니다**. `/usage` 는 대화형 전용입니다. 게다가 한도를 토큰으로 환산하는 공식을 Anthropic 이 공개하지 않습니다 |

#### `--max-budget-usd` 는 «금액»을 막습니다 — 디스크 용량이 아닙니다

이름 그대로 **달러 금액 상한**입니다. 그 `-p` 실행이 쓰는 API 비용이 정한 금액을 넘으면
**그 실행을 중단**합니다. 디스크·메모리·토큰 수가 아니라 **돈**입니다.

🔴 **다만 «구독 인증에서 이게 어떻게 동작하는지»는 [미검증]입니다.** 구독은 달러로
과금되지 않으므로 둘 중 하나입니다 — ① 환산 비용을 계산해 막는다 ② 구독 인증에서는
무시된다. **Phase 1 에서 반드시 잽니다.** ②라면 상한을 직접 세야 합니다
(세션 로그의 토큰을 더해 러너가 끊는 방식).

그리고 **디스크는 이 플래그가 안 막으므로 따로 봅니다** — 착수 전 여유 공간 검사(§9.2).

> **[실측] 가설 하나를 세웠다가 틀렸습니다.** 세션 로그에 `apiBlockIndex` 라는 필드가 있어
> 「5시간 블록 번호」인 줄 알았는데, **같은 초에 0~3 이 함께 찍힙니다** — 5시간 창이 아니라
> **한 턴 안의 API 요청 번호**였습니다. 이걸 안 재고 썼으면 한도 계산이 통째로 틀렸을 겁니다.

**그래서 설계는 「남은 양을 읽는다」가 아니라 «내가 정한 예산을 지킨다»로 갑니다.**

1. 단계마다 `--max-budget-usd` 로 상한을 건다 (초과 시 그 단계만 중단)
2. 러너가 세션 로그를 더해 **그 밤의 총 소비를 기록**한다
3. 미리 정한 **밤 예산**을 넘으면 **남은 단계를 다음 밤으로 미룬다**
4. 그래도 한도에 부딪히면 §8.3 의 「그 단계만 재시작」으로 복구한다

**#5 의 "한도 체크하면서 가능해?"에 대한 답**: 남은 양은 못 읽지만,
**쓴 양은 정확히 알고 상한은 확실히 겁니다.** 실무적으로는 이게 더 안전합니다 —
남은 양을 읽는 방식은 그 값이 틀리는 순간 전부 무너집니다.

## 9. #8 — 엣지케이스와 예외처리

**리서치 파이프라인만의 함정**이 따로 있습니다. 여기가 설계의 진짜 어려운 부분입니다.

### 9.0 실패를 셋으로 가른다 — 특히 「③ 그 외」가 무엇인가

**①도 ②도 아닌 실패 전부**입니다. 성질이 달라서가 아니라 **성질을 모르기 때문에** 한 칸입니다.

| 갈래 | 무엇 | 어떻게 |
| --- | --- | --- |
| **① 한도 소진** | 5시간·주간 한도에 부딪힘 | 그 단계를 표시하고 **깨끗이 종료.** 다음 밤이 이어받는다. **재시도하지 않는다** — 해봐야 또 막힌다 |
| **② 인증·과금 거부** | 토큰 만료 · 정책 변경 · 결제 실패 | **사람에게 알리고 정지.** 재시도가 의미 없고, ①·③과 섞이면 **며칠 조용히 안 도는 상태**가 된다 |
| **③ 그 외** | 네트워크 순간 끊김 · 웹페이지 500 · 산출물 JSON 깨짐 · 세션이 이상하게 끝남 · **그리고 분류에 실패한 미지의 실패 전부** | **N번까지 다시 해보고**, 안 되면 그 단계만 포기하고 **다음 밤으로 넘긴다** |

#### 「상한」이 왜 반드시 있어야 하나

**상한이 없으면 밤새 같은 실패를 반복하며 토큰을 태웁니다.**
아침에 보면 **예산은 다 썼고 산출물은 0장**입니다. 그리고 그런 밤은
「실패했다」가 아니라 「아무 일도 없었다」처럼 보여서 **며칠 지나서야 알아챕니다.**

**모르는 실패를 ③으로 떨어뜨리는 것이 핵심입니다.** 분류기가 새 실패 모양을 못 알아봐도
파이프라인은 상한 안에서 멈추고, **원문은 로그에 남아** 다음에 그 모양을 분류기에 가르칠 수 있습니다.
분류기를 완벽하게 만드는 대신 **모를 때 안전한 쪽으로 떨어지게** 만드는 설계입니다.

### 9.1 리서치 내용의 함정

| 상황 | 그냥 두면 | 어떻게 |
| --- | --- | --- |
| 검색 결과가 **전부 SEO 스팸·광고** | 쓰레기로 문서를 채운다 | 소스 유형을 **A(논문/재현코드)·B(저명 블로그)·C(익명 포럼)** 로 태깅. **C 만으로는 판정 불가** |
| **열 곳이 같은 말 = 한 원본의 복제** | "열 곳에서 확인"이라 적는다 | 6번 칸 계보표. **복제를 뺀 수**를 적는다 |
| 유료 논문이라 **초록만** 보임 | 초록만 보고 단정한다 | 「미검증」으로 적고 판정을 유보 |
| **없는 논문·URL 을 지어냄** | 읽어선 구별 안 됨 | **게이트가 URL 을 전부 호출**. 죽으면 미완성 (§6) |
| 원래 **존재하지 않는 매매법** | 억지로 문서를 채운다 | 찬성 근거 0건이면 **「실체 없음」으로 조기 종료** — 정상 결과다 |
| **이미 원장에 있는 후보** | 같은 걸 또 판다 | 착수 전 원장 대조. 같으면 건너뛴다 |
| 결론이 **과장됨** | 아침에 내가 속는다 | 2번 칸 판정에 **반드시 이유**. 11번 칸(미검증)이 비면 오히려 의심 |
| 반증을 **형식적으로 한 줄만** | 게이트를 통과해버림 | 반증에도 **URL 필수**. 별도 세션이라 형식적으로 쓸 이유가 없음 |

### 9.2 운영의 함정

| 상황 | 어떻게 |
| --- | --- |
| **한도 소진으로 중단** | 그 단계만 다음 밤 재시작 (§8.3) |
| **네트워크 실패** | 1회 재시도 → 실패 시 그 단계 스킵·이월. **「인터넷이 안 된다」로 결론짓기 전에** 전역 규칙의 3단계 진단(자격증명 → DNS → 샌드박스)을 먼저 돈다 |
| **Windows 가 잠들어 트리거 실패** | 러너가 「마지막 성공 시각」을 보고 **하루 이상 걸렀으면 다음 실행에서 알린다** |
| **같은 밤 두 번 실행** | 실행 폴더를 **날짜로 잠근다**. 이미 있으면 이어받기 |
| **반쯤 쓰다 만 산출물** | **임시 파일에 쓰고 성공했을 때만 rename.** 반쯤 쓴 문서가 완성본 자리에 남지 않게 |
| **디스크 가득** | 착수 전 여유 공간 검사. 부족하면 시작하지 않는다 |

#### 모르는 채로 짓되, «계측을 심어서» 짓습니다

미리 못 재는 것 때문에 생기는 진짜 사고는 **러너가 한도 소진을 버그로 오인해

- 실패를 셋으로 가른다 — ① 한도 소진 ② 인증·과금 거부 ③ 그 외

### 11.1 구현하며 확정된 것 (2026-09-12)

#### CLI 계약 — `claude --help` 전수 확인

설계가 사실로 전제한 플래그를 전부 확인했습니다. **전제는 맞았고, 넷이 새로 나왔습니다.**

| 플래그 | 판정 |
| --- | --- |
| `--tools` · `--max-budget-usd` · `--json-schema` · `--session-id` · `--permission-mode bypassPermissions` | **쓴다.** 전부 실재하며 `--print` 전용 제약도 설계와 일치 |
| `--setting-sources <user,project,local>` | 🔴 **쓰지 않는다.** 막으려던 위험(전역 설정 유입)은 **이미 구조적으로 불가능**하다 — `~/.claude` 를 마운트하지 않고 HOME 이 빈 폴더로 시작한다. 반면 이 플래그가 **저장소 자신의 스킬까지 가리는지는 [미검증]**이고, 가린다면 **에러 없이** 리서치 규율만 사라진다. **얻는 것이 0 이고 잃을 수 있는 것이 그것이라** 넣지 않았다 |
| `--no-session-persistence` | 🔴 **쓰지 않는다.** 세션 로그가 안 남아 폭주 감지 fallback 이 사라진다 |
| `--disable-slash-commands` | 🔴 **쓰지 않는다.** 이 저장소의 리서치 스킬이 안 뜨는데 **에러는 안 난다** — 문서는 그럴듯하게 나오고 규율만 빠진다 |
| `--effort <low\|medium\|high>` | 아직 안 쓴다. 밤 예산 조절 레버로 존재만 기록한다 |

#### 컨테이너 — Claude 를 «npm» 으로 넣는다

**[실측]** `python:3.12-slim` 에는 `curl`·`node`·`npm`·`git` 이 **하나도 없습니다**(`python3` 만).
이미지는 **1.36GB**, 안에서 `claude 2.1.269` 가 uid 1000 으로 뜹니다.

**탈락안은 네이티브 인스톨러입니다.** 호스트의 `claude` 가 그 방식이고
(`~/.local/share/claude/versions/`, **240MB ELF 바이너리**, npm 전역에 없음), 아치를 스스로
판별한다는 장점이 있습니다. 그런데 이 컨테이너는 **HOME 을 호스트 폴더로 마운트**하므로
**빌드 시점의 HOME 과 실행 시점의 HOME 이 달라 설치본을 못 찾습니다.**
npm 전역 설치는 `/usr/local/lib/node_modules` 에 들어가 **HOME 과 무관하고 모두가 읽을 수 있어**
그 문제가 없습니다. 대가는 Node 런타임이 얹히는 것입니다.

> **「멀티아치 베이스만 쓴다」는 결정은 베이스만 덮고 설치 방식은 안 덮습니다.** 둘은 따로 정해야 합니다.

#### 🔴 컨테이너 안 `claude` 의 HOME 은 «저장소 밖» 호스트 폴더

자리가 셋인데 **나머지 둘은 각각 다른 쪽으로 터집니다.**

| 자리 | 무슨 일이 나나 |
| --- | --- |
| 저장소 **안** | 인증 상태와 세션 로그가 bind mount 를 타고 저장소에 생긴다. **PUBLIC 이고 git 이력은 되돌아가지 않는다** |
| 컨테이너 **휘발 공간** | 컨테이너와 함께 죽어 세션 로그가 사라진다. **폭주 감지 fallback(토큰 합산)과 되붙기가 둘 다 없어진다** |
| 저장소 **밖** 호스트 폴더 | 둘 다 피한다 |

**mac 과 공유되지 않지만 잃는 것이 없습니다** — 되짚을 로그는 러너가 `runs/` 에 쓰고,
`--resume` 과 5시간 창 합산은 **기계를 옮기면 어차피 못 씁니다.**

> **그래서 러너가 비용·토큰·소요 시간을 «자기 손으로» 결정 로그에 적습니다.**
> 그래야 밤 예산 집계가 저장소 안에서 완결되어 기계를 옮겨도 기록이 git 으로 따라옵니다.
> **[중요] 토큰을 셀 때 `cache_read_input_tokens` 를 빼야 합니다** — 캐시가 도는 상황에서
> 그 값은 새 입력 토큰보다 한 자릿수 크고, 그대로 더하면 **예산 근거가 그 배수만큼 틀어집니다.**

#### [실측 2026-09-12] `--output-format json` 의 응답 모양 — §8.3 의 [미검증] 둘을 닫는다

컨테이너에서 **잘못된 토큰으로** 한 번 불러 받은 실제 응답으로 확인했습니다(비용 0).

| 확인한 것 | 값 |
| --- | --- |
| 실제 필드 | `result` · `total_cost_usd` · `session_id` · `is_error` · `subtype` · `num_turns` · `duration_ms` · `usage` |
| `usage` 안 | `input_tokens` · `output_tokens` · `cache_creation_input_tokens` · **`cache_read_input_tokens`** · `output_tokens_details` |
| 인증 실패의 모양 | `result` 가 **"Invalid auth token - Fix external auth token - ..."** |

🔴 **`is_error: true` 인데 종료 코드가 `0` 이었고 `subtype` 은 `"success"` 였습니다.**
종료 코드나 `subtype` 으로 성패를 가르면 **실패가 성공으로 통과합니다.** `is_error` 만 믿습니다.

🔴 **그리고 그 인증 실패가 처음에는 「그 외」로 분류돼 3번 재시도됐습니다.** 분류표의 추정 문구
(`invalid api key` 등) 중 어느 것도 실제 문구에 걸리지 않았기 때문입니다 — §9.0 이 「②를 ①·③과
섞으면 며칠 조용히 안 도는 상태가 된다」고 경고한 바로 그 모양입니다.
**그 원문으로 표를 고쳤고, 이것이 「처음 부딪히는 날 로그가 분류기를 가르친다」의 첫 사례입니다.**

#### [실측 2026-09-12] 중첩 세션 차단은 «컨테이너 안에서는» 걸리지 않는다

Claude Code 세션 안에서 `claude -p` 를 직접 부르면 중첩 세션으로 막힙니다. 그런데
**컨테이너에서는 안 막힙니다** — `docker run` 이 부모 환경을 상속하지 않고, `run.sh` 가
`--env` 로 셋(`HOME` · `CLAUDE_CODE_OAUTH_TOKEN` · `TZ`)만 넘겨 **중첩 표식(`CLAUDECODE` 등)이
컨테이너에 들어가지 않기** 때문입니다.

> **과금 가드를 위해 만든 「넘길 변수를 명시적으로 나열한다」가 부수적으로 이것까지 해결했습니다.**
> 그래서 밤 실행과 실측을 **Claude Code 세션 안에서도 컨테이너 경유로 할 수 있습니다.**
> 호스트에서 직접 부르는 개발용 경로(`poetry run python scripts/run_night.py`)는 여전히 막힙니다.

#### [실측 2026-09-12] 마운트 대상 폴더는 «미리» 만들어야 한다

`docker run -v` 가 가리키는 호스트 폴더가 없으면 **도커가 root 소유로 만듭니다** —
`--user 1000:1000` 을 줘도 그렇습니다(컨테이너가 뜨기 «전»에 생기므로).
그래서 `run.sh` 가 `mkdir -p "$AGENT_HOME"` 을 먼저 합니다. 그 줄을 지우면
에이전트 HOME 이 root 소유가 되어 컨테이너가 아무것도 못 씁니다.

#### [실측 2026-09-12] 밤을 실제로 완주시켜 얻은 것 — §8.3·§8.4 의 [미검증]이 닫혔다

#### 🔴 [실측] 에이전트는 「다른 말 없이 JSON 만」을 지키지 않는다

| 갈래 | 실제 문구 | 추정이 왜 빗나갔나 |
| --- | --- | --- |

| 방식 | 문제 |
| --- | --- |

**지금은 ①입니다.** ②·③은 후보가 실제로 쌓여 「①이 불편하다」가 느껴진 뒤에 봅니다 —
